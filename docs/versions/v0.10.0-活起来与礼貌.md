# v0.10.0 — 活起来 · 有礼貌 · 有手感

## 目标

上一轮「作为桌宠缺什么」的体检结论里，最伤体验的是三件事：

1. **不会动**：10 个状态 = 10 张图硬切，动感全靠用户自带 GIF——缺逐帧序列支持。
2. **没礼貌**：只有托盘里那句「暂停 1 小时」，夜里照样弹「该站起来啦」——缺免打扰时段。
3. **没手感**：拖到屏幕边上就走了，永远对不齐——缺贴边吸附。

本版把这三件事做完，顺带让新上线的素材页认识帧序列（否则导入会把 `_001` 改成 `_2`，
直接打乱播放顺序）。里程碑定名 v0.10.0。

## 功能清单

- [x] 帧序列解析：`{state}_001.png`（**正好三位零填充**）为帧，按序号播放，150ms/帧。
- [x] 帧序列判定：同状态 ≥2 帧才成动画；序列**不参与**变体随机轮换（自己会动，再换图只会闪）。
- [x] 帧预加载：所有帧提前 `new Image()`，切换走缓存，避免透明背景上闪白。
- [x] 素材页识别帧号：导入 `开心_001.png` 保留成 `happy_001.png`；同帧重导覆盖该帧、不打乱顺序；页面提示"检测到帧序列"。
- [x] 拖拽结束贴边吸附：距工作区边缘 ≤24 物理 px 就贴过去（左右/上下各取近侧），不做全局 clamp。
- [x] 免打扰时段：设置里可开关并按整点配置（支持跨午夜），时段内站立提醒不弹、截止时间推到时段结束。
- [x] 版本对齐 0.10.0，Windows 安装包 `run_here/windows/Mochi_0.10.0_x64-setup.exe`。

## 文件级实现细节

### 素材解析（`src/services/pet-assets.ts`）

- 新增 `AssetFileParts` + `parseAssetFile(name)`：一次拿到 `{ state, ext, frame, variant }`。
  **位数决定语义**：1~2 位数字是变体，正好 3 位是帧，4 位以上按状态名一部分（不生效）。
- `PetVariant` 增加可选 `frames?: string[]`（长度 ≥2 时渲染层播放）。
- 新增 `buildVariants(entries)`：把同名状态的条目分成"帧组"与"普通变体"，帧 ≥2 合成**一个**变体。
- `listVariants` 现在**先剔除加载失败的 URL，再决定"用户优先还是内置兜底"**（顺序错了会出现
  「用户图坏了显示空白」而不是回退内置——被既有单测当场抓到）。

### 渲染（`src/pages/pet/PetApp.tsx`）

- 新增 `FRAME_INTERVAL_MS = 150` 与 `useFrameUrl(asset)`：`setInterval` 推进帧索引。
  依赖用 `frames.join("|")` 而不是数组引用——数组每次解析都是新对象，直接进依赖会让计时器
  每个渲染周期重置（动画永远停在第一帧）。
- 轮换逻辑排除帧序列：`!v.animated && !(v.frames && v.frames.length > 1)`。

### 导入（`src/services/pet-asset-import.ts` + `src/pages/chat/AssetsTab.tsx`）

- `frameOfFileName(name)`：`开心_001.png` → 1；`开心_2.png` → null。
- `targetFileName(...)` 增加 `frame` 参数：帧名 = `{state}_{:03}.{ext}`，**不避让、不递增**
  （挪位就是错位）；同帧重导=更新那一帧。
- `savePetAsset(state, ext, base64, frame)`、`PendingFile.frame`、列表里的「帧 001」角标、
  批量导入时的序列提示（"会按 001/002 顺序循环播放"）。

### Rust（`src-tauri/src/lib.rs`）

- `save_pet_asset` 增加 `frame: Option<u32>`：给了序号就落成 `{state}_{:03}.{ext}` 并允许覆盖同名帧；
  没给仍走 `next_asset_file_name`（变体绝不覆盖）。
- 新增 `SNAP_THRESHOLD_PX = 24`、`snap_to_work_area`（纯函数，可单测）、`snap_pet_to_edges`。
- 拖拽收尾处**把锁的作用域收紧到"只算状态"**：窗口 API（`outer_position`/`set_position`）
  移到锁外调用——本文件开头警告过"持锁调 UI 线程"的死锁形态。

### 免打扰（`src/services/quiet-hours.ts`、`settings.ts`、`timers.ts`、`SettingsTab.tsx`）

- 新模块两个纯函数：`isQuietHour(now, start, end)`（`start > end` 表示跨午夜；
  `start === end` 视为未设置）、`quietEndAt(now, start, end)`。
- 设置新增 `quietHoursEnabled / quietStartHour / quietEndHour`（默认关、22→8），`normalize` 夹紧 0~23。
- `StandupService.tick`：静默时段内 `return`，并把 `deadline` 推到 `quietEndAt`
  （**推**而不是清零：恢复后只响一次，不补一串欠账）。
- 设置页：免打扰开关 + 两个整点下拉（`HOURS` 0~23），并注明"只静默站立提醒"。

## 设计取舍

**① 为什么用"三位零填充"标记帧，而不是新前缀**
用户素材多来自 Aseprite / Spine 这类工具，导出天然是 `001`、`002` 这种零填充；而变体是手写的
`_2`、`_3`。用位数区分，既不改动 v0.2.0 已生效的变体语义，也不需要用户学新前缀。
代价：`idle_012.png` 是帧、`idle_12.png` 是变体——这条规则有点隐晦，所以写进了
`docs/pet-assets.md` 的表里，并在导入页给出「帧 001」角标。

**② 为什么帧序列优先于变体、且不参与轮换**
同时存在 `idle.png` 与 `idle_001..003.png` 时，用户做动画的意图明显更强；而序列本身就是
动态的，再叠加 5~9 秒随机换图，观感是"闪断"。所以序列一旦成立就独占该状态。

**③ 为什么不给帧序列做可变帧率**
v1 只支持等间隔 150ms。理由是：可变帧率需要新的命名约定（如 `001@120.png`）或外部配置，
而绝大多数桌宠素材是匀速呼吸/摆动；想更精细就该用 GIF/WebP。先把"能放动画"做到，
再谈参数化。

**④ 贴边吸附为什么只吸"近处"，且不做全局 clamp**
用户把宠物故意放在屏幕边缘露一半是常见用法（遮一半更不打扰）。全局 clamp 会持续把它拉回，
很烦。24 物理 px 在 100%/150% 缩放下约 24/16 逻辑 px，是"看起来已经贴着"的距离。

**⑤ 免打扰为什么只静默站立提醒**
自定义提醒与番茄钟是**用户明确下令**的时间点，静默它们等于吞掉指令——这比打扰更糟。
免打扰针对的是"系统自己决定要说话"的那一类（站立提醒）。

**⑥ `start === end` 为什么按"未设置"处理**
这种配置在语义上等于"全天静默"。它最容易由下拉框误配产生，一旦生效就是"提醒永远不响"的
沉默故障，比多弹几次更难排查——所以明确排除。

**⑦ 关闭静默后不会立刻恢复提醒（已知语义）**
`reloadConfig` 只在 `standupIntervalMin` 变化时才 `rearm`。所以：静默期间 deadline 被推到
时段结束，中途关掉开关不会让提醒立刻响，要等原 deadline 或点一下宠物重置。这是**有意保留**的
（避免用户改配置时被立刻打断），已记录，若后续觉得别扭再改。

## 踩坑与解决

### ① 回退链被自己的重构弄坏了

把 `listVariants` 改成"先分组再过滤"之后，既有测试 `用户图加载失败后回退内置` 直接红：
失败 URL 被剔得太晚，导致"用户图全坏"时返回空池而不是内置形象。修法：**先剔除失败 URL，
再判用户/内置优先级**。这条测试是 v0.2.0 写的，这次正好拦住回归。

### ② 帧计时器被数组引用"重置"

`useEffect` 依赖 `frames` 数组时，每次解析产生新引用 → 计时器重建 → 索引永远回到 0。
改成依赖内容摘要 `frameKey = frames.join("|")`。

### ③ 拖拽收尾持锁调窗口 API

原代码在 `Mutex<DragMotion>` 的 guard 内直接 `emit`。加吸附时要调 `outer_position`/`set_position`，
必须把 guard 收进一个小作用域，先算出"是否放手"，出作用域再动窗口。

### ④ 对照实验一开始"结论无效"

第一次验证免打扰：关掉开关后 80 秒仍不弹——看上去像"静默开关没生效"，实际是**静默期间
deadline 被推到了时段结束**，关开关不会重排。重做对照时改为"重启进程让 deadline 重建"，
才拿到干净的对照结果（+60s 触发）。

### ⑤ tsc 的 noUnusedLocals 拦下一个多余变量

`AssetsTab` 里顺手算了个 `frameCount` 没用上，`pnpm check` 直接报 TS6133。
