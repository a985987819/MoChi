# P1-02 通知点击回应用 + 应用内提醒中心

- **状态**：open
- **优先级**：P1（提醒"发出去"了，但用户找不到"发过什么"）
- **依赖**：无
- **涉及文件**：`src/services/notifications.ts`、`src/pages/chat/PomodoroTab.tsx`（或新 Tab）、
  `src/services/reminders.ts`、`src-tauri/src/lib.rs`（若走原生通知动作）

## 背景

现在通知只负责"响一下"：

- **点系统通知没反应**（`sendNotification` 没有接 action）；
- **没有提醒历史**：错过的、已过期合并的（v0.11.0 的 `reminder:batch`）只在数据库里，
  用户没有任何界面能看到"昨天提醒过我什么"；
- 未确认的提醒（`status='fired' AND acknowledged_at IS NULL`）没有可见入口。

## 目标

1. 点系统通知 → 聚焦并打开聊天窗（最好直达"提醒"区块）；
2. 新增**提醒历史**列表：数据源 `reminders` 表（`fired` / `cancelled` / `active` 分组），
   显示时间、正文、状态；支持"再次提醒"（一键 +30 分钟 / 明天同一时间）；
3. 未确认提醒的角标：宠物右键菜单与聊天窗 Tab 上显示数量（复用 `v0.9.0` 待办计数那套思路）。

## 实现建议

- **通知点击**：先调研 `tauri-plugin-notification` 的 action 能力（Windows 需要 toast 按钮/激活回调，
  当前插件版本可能只支持"点击打开应用"这一层）。若插件不支持，退化方案：
  通知文案里写"点开麻薯查看"，并在应用内用历史中心兜底——**不要为此引入第二个通知插件**。
- **历史读取**：`ReminderStore` 已有 `listActive()`；新增 `listHistory(limit)`（按 `fire_at DESC`），
  注意分页（表会增长）。
- **"再次提醒"**：本质是 `create(text, now + delta)`，复用现有 Store，不要写第二条插入路径。
- **合并提醒**（v0.11.0）：`reminder:batch:*` 不是数据库行，历史里用"该时段合并了 N 条"的方式呈现，
  需要额外记录（建议给 `reminders` 加 `batch_id` 或在历史读取时按 `fired_at` 聚合同一秒的多行）。

## 验收标准

- [ ] 历史列表能显示三类状态，且分页/上限生效（单测：纯函数分组与截断）。
- [ ] 点通知能打开聊天窗（真机确认；若插件不支持，必须在文档里写明原因与替代路径）。
- [ ] 未确认数量与右键菜单显示一致（跨窗口事件，不要各自查库）。
- [ ] 空态文案引导用户可以说什么（"帮我明天九点提醒交周报"）。

## 坑

- 提醒正文可能很长：列表要 `-webkit-line-clamp`（项目里已有类似写法可参考）。
- 不要把历史中心做成第二个"聊天记录"，它只回答"提醒过什么"。
- 跨窗口一致：`remindersChanged` 事件已有，别新造一套。
