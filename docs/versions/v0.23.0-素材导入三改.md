# v0.23.0 — 素材导入三改：全面替换默认形象 + 每状态上传 + 点击复制命名

> 用户三项诉求一次到位。2026-11-18。

## 目标

1. **导入即全面替换默认形象**：用户目录有任何素材后，缺失状态不再回落内置麻薯
   （否则"换成猫的 happy + 默认麻薯的 idle"混搭出戏）；占位 SVG 接管缺失状态。
2. **每个状态独立上传**：状态卡片上的「上传」按钮直接为该状态选图，免去通用入口
   的手动归位。
3. **点击复制命名**：每个状态卡片提供两枚规范文件名 chip（`{状态}.png` 基础形态、
   `{状态}_001.png` 帧序列），点击即复制——给自有素材改名时不用回文档查命名约定。

## 设计取舍

1. **"有任何素材"而不是"逐状态"触发替换**：用户换形象是整体行为（一套猫素材），
   逐状态判断会保留混搭——正是用户要消除的场景。fresh install（目录空）保持内置，
   首次观感不受影响。
2. **用户图损坏 → 占位而非内置**：与缺失状态同一语义（角色一致性优先）；占位 SVG
   标注状态名，用户立刻知道"这个状态缺图或图坏了"。
3. **每状态上传仍走确认列表**：选完先进「待导入」批次（可改状态/移除），不直接落盘
   ——改名是不可逆的用户素材操作，猜错比多一次点击更糟（沿用 v0.9.2 的安全设计）。
4. **两枚命名 chip 而非一份说明文字**：点击即复制的交互成本低于"阅读约定再手拼"；
   帧序列名 `_001` 单独给一枚，因为它是逐帧动画的入口形态（v0.10.0）。
