# 任务板（docs/tasks）

> 给**人类协作者与 AI agent**共用的工作队列。AGENTS.md 是纪律，这里是待办。

## 为什么有这个目录

这个项目是单人 + 多 agent 协作开发的。口头约定会丢，issue 又不联网，所以把「还欠什么、
做到哪一步、交接注意什么」写进仓库，任何 agent 打开就能接活，不必重新体检一遍代码。

## 怎么用（认领协议）

1. **先读** `AGENTS.md`（硬约束）→ 本文件 → 目标任务文件。
2. **认领**：把任务文件头部的 `状态` 改成 `claimed: <你的名字>`，同时在 `TASKS.md`
   表格里同步。**认领单独一个 commit**（`chore(tasks): 认领 P0-01`），避免与他人撞车。
3. **动工**：只改任务文件里列出的「涉及文件」；需要跨域改动时，先在 `TASKS.md`
   的「占用」列登记你要碰的额外模块。
4. **收口**：任务文件里追加一节 `## 实施记录`（做了什么 / 取舍 / 验证结果 / 遗留），
   状态改 `done`，并同步 `TASKS.md`、版本文档、`CHANGELOG.md`。
5. **一个任务一个 commit**（或一组紧密相关的小 commit），正文按 `.gitmessage` 的结构写。

> 同时只能认领一个任务。任务之间的依赖写在各自文件里，有依赖就先别开工。

## 状态定义

| 状态 | 含义 |
|---|---|
| `open` | 可以认领 |
| `claimed: <name>` | 已认领，别动 |
| `blocked: <原因>` | 被外部条件卡住（需用户决策 / 缺设备 / 依赖未完成） |
| `done` | 已完成并合入；文件保留作为决策与踩坑记录 |

## 完成的定义（DoD）

一个任务算完成，必须同时满足：

- [ ] 代码带**教学型注释**（解释为什么，而不是重复代码在做什么）；
- [ ] 有单测（纯逻辑必须可测；不可测的交互写清"为什么不可测 / 怎么手工验"）；
- [ ] `pnpm check` + `pnpm test` + `cargo test` 全绿；
- [ ] 版本文档 `docs/versions/vX.Y.Z-*.md` 记录文件级实现与踩坑；
- [ ] `docs/roadmap.md` 与 `CHANGELOG.md` 同步；
- [ ] 用户可见的变化，在交付说明里写清"需要你亲自验证什么"。

## 优先级约定

| 级别 | 含义 | 判断标准 |
|---|---|---|
| P0 | 影响"像不像桌宠 / 会不会烦人" | 不做的话用户会明显觉得不对劲 |
| P1 | 影响留存与闭环 | 功能有了但没用透、有半成品感 |
| P2 | 工程与体验欠账 | 不影响日常使用，但会拖慢后续开发 |

## 目录

- `TASKS.md` —— 总表（含已完成项与提交号，便于考古）
- `P0-*.md` / `P1-*.md` / `P2-*.md` —— 每个未完成任务一个文件
- 已完成任务的文件保留，状态标 `done`，`: 实施记录` 里有取舍与踩坑

## 与其它文档的关系

| 文档 | 作用 |
|---|---|
| `AGENTS.md` | 硬约束（提交纪律、代码规范、部署红线） |
| `docs/roadmap.md` | 版本路线与验收标准（唯一进度事实源） |
| `docs/versions/` | 每个版本做了什么（事后记录） |
| `docs/learning/` | Agent 开发知识（教学） |
| `docs/tasks/`（本目录） | **事前**待办与交接（谁在做什么） |

`docs/tasks/` 负责"接下来做什么"，`docs/roadmap.md` 负责"这一版算不算完成"，两者不重复。
