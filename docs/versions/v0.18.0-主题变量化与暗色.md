## 设计取舍

1. **深色是暖棕灰不是反色**（任务单的坑）：奶油粉对应 `#2a2426` 暖棕系——
   冷灰会显得硬；粉色系整体保留（品牌色不随主题翻转）。
2. **粉色拆"填充族"与"文字族"**：fill（白字色块）深色下保持饱和（白字对比不塌）；
   text（浅底粉字）深色下提亮到 ≥4.5。一个 accent 令牌兼任两种角色必然翻车。
3. **浅色也有三处被加深**（对比度自动化揪出来的原设计欠账）：
   `--text-muted` #8a7f7a→#7d716c（4.75:1）、`--text-faint` #a39690→#8f817b（3.8:1）、
   `--text-faint2` #c4b6bd→#8f8491（3.6:1，它是可点的 × 按钮）、
   `--accent-text` #c94a5a→#b3455a（4.9:1，取原调色板最深的粉）、
   success/warn 文字档同步加深。视觉差异都在"更清晰一点"的量级。
4. **对比度测试解析 theme.css 而不是硬编码值**：令牌被改而测试没改时测试会红，
   不会静默漂移。元数据档（时间戳/占位）阈值 3：12px 灰字强行 4.5 会毁掉层次，
   WCAG 次要信息档就是 3。
5. **主题切换用 `data-theme` 属性而不是媒体查询**："跟随系统"由 JS 写属性
   （matchMedia 即时订阅），三档语义统一走一条路径，CSS 只认属性——避免
   media query 与 attribute 双分支各写一套。

## 踩坑与解决

- `#ffffff` 同时是卡片底与气泡 inset 高光——先整句替换 `inset 0 1px 0 #ffffff`
  再跑全局映射，否则高光被替换成卡片底色。
- 替换用 hex 边界正则（`(?<![0-9a-fA-F])#fff(?![0-9a-fA-F])`），防 `#fff` 吞掉
  `#fffaf0`。
- 一次性迁移脚本放临时目录不入库（映射表本身在 theme.css 注释与 git diff 里
  可追溯）。

## 追加（2026-11-18，收尾复查修复）

收尾复查用「每个用到的 var 都必须在 theme.css 定义」的反向校验时，发现 **10 处
「粉底白字」被机械迁移成了 color: var(--bg-surface)**（用户气泡/主按钮/待办勾选/
welcome 主按钮等）——浅色下 bg-surface 恰好也是白色所以没炸，深色下会变成
深字配饱和粉底（对比度 ~1.6:1）。这正是取舍 §2 预判的陷阱：fill 类上的白字
不随主题翻转。修复：新增 `--text-on-accent`（两套主题恒白 #ffffff），10 处
全部改用（含 `todo-row__check:disabled` 的 border-accent 底）。复核命令：
`grep -rn 'color: var(--bg-surface)' --include='*.css' src` → 0 处。
构建：0.19.0 NSIS/MSI（run_here/windows/）已含此修复。
