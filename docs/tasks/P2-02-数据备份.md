# P2-02 数据备份 / 导出 / 迁移

- **状态**：open
- **优先级**：P2（换机/重装会丢长期记忆与待办）
- **依赖**：无
- **涉及文件**：`src/pages/chat/SettingsTab.tsx`（关于/危险区）、`src/services/db.ts`、
  `src-tauri/src/lib.rs`（打包与还原命令）、`src/services/pet-asset-import.ts`（素材目录）

## 背景

用户数据全在 `{appData}/com.mochi.pet/`：

| 文件 | 内容 |
|---|---|
| `settings.json` | 提供商/模型/Key/称呼/计时/免打扰等 |
| `mochi.db` | 聊天历史、待办、长期记忆、提醒 |
| `pet-assets/` | 用户自定义宠物素材 |

现在只能"打开数据目录"手动拷。重装、换机、误删都没有恢复路径。

## 目标

- **导出**：一键生成 zip（三个数据源 + `manifest.json` 记录版本与导出时间）；
- **导入**：选择 zip → 校验版本 → 提示"将覆盖当前数据" → 备份现有数据后再还原；
- **可选**：导出时默认**不含 API Key**（给一个勾选"包含密钥"），避免备份文件变成凭据泄露源。

## 实现建议

- Rust 侧做 zip（`zip` crate）与还原：前端没有文件系统权限（`AGENTS.md` 权限最小化），
  导出路径用 Tauri 的保存对话框需要 `tauri-plugin-dialog`——**先确认是否愿意加这个插件**；
  否则退化方案：导出到固定目录（`appData/backups/mochi-YYYYMMDD-HHmm.zip`）并在 UI 里 reveal。
- **SQLite 一致性**：导出前执行 `PRAGMA wal_checkpoint(TRUNCATE)`，否则 `-wal` 里的最新数据会漏；
  导入后需要重启（数据库连接已打开）。
- **导入安全**：解压前校验路径（防 zip slip）、限制总大小、只允许已知文件白名单。
- 版本兼容：`manifest.json` 里写 `schemaVersion`；旧备份导入时按现有 `ensureSchema` 逻辑补齐列。

## 验收标准

- [ ] 导出包含三个数据源 + manifest；`settings.json` 在"不含密钥"模式下 `apiKeys` 被清空（单测纯函数）。
- [ ] 导入：合法 zip 成功、缺文件报可读错误、非法路径被拒（单测 + 手工）。
- [ ] 覆盖前自动生成一份 `pre-restore` 备份。
- [ ] 文档写清"备份文件里有没有明文 Key"。

## 坑

- `mochi.db` 正在被两个窗口使用，直接复制可能拿到半写状态——务必先 checkpoint。
- 素材目录可能很大（用户塞了几十 MB 的 GIF），导出要显示进度或至少给体积预估。
- 不要覆盖用户正在编辑的设置：还原后要求重启，而不是热加载。
