## 文件级实现细节

### 传输层（src/agent/providers/）

- `types.ts`：四角色判别联合 + JsonSchemaObject 迷你类型（v0.4.0 校验器共用）；**tool-calls 组装后一次发出**的设计决定落实在此（StreamEvent 定义）。
- `sse.ts`：`parseSSE(res)` 纯函数生成器；releaseLock 在 finally。
- `openai-compatible.ts`：连接阶段重试（仅 fetch 头之前，流开始后绝不重试）；`AbortSignal.any` 合并超时与用户 signal；单包 JSON 损坏跳过不炸流；`serializeMessage` 支持 assistant.toolCalls → tool_calls（v0.4.0 协议就位）。
- `presets.ts`：五预设；模型列表标注"以官方文档为准"。
- `index.ts`：`createProvider(settings)` 工厂——UI 永远只 import 这里 + 类型。

### 服务层

- `settings.ts`：store 单例 + normalize（防脏数据）；`isProviderReady` 闸门；Key 每提供商分桶。

### UI 层

- `ChatApp.tsx`：标题栏拖动区 + Tab 切换；`ChatTab.tsx`：协议消息组装（历史全量重发）、流式增量拼到最后一条 assistant、错误条可关闭；`SettingsTab.tsx`：即时落盘（无保存按钮——低频操作）、测试用**当前表单值**现场建 Provider。
- Rust：tauri-plugin-store 注册；capability + `store:default`。

### 依赖变化

- npm：+ `@tauri-apps/plugin-store`、`react-markdown`、`remark-gfm`；
- cargo：+ `tauri-plugin-store`。

## 设计取舍

1. **自写 fetch 而非 openai SDK**：教学（看穿协议）+ 零依赖（02 §5，维持既定裁决）。
2. **连接阶段重试、流阶段不重试**：流中途重试会重复输出；重试语义只在"还没开始说"时成立。
3. **流式消息纯文本、完成消息 markdown**：流式逐帧跑 remark 开销大且光标难贴合；完成的定稿才值得富排版。
4. **无 Key 闸门在发送前拦截**（isProviderReady）：错误前置到动作前，而不是等 HTTP 401。
5. **设置即时落盘**：低频配置无"未保存"心智负担；表单值与持久值永不漂移。
