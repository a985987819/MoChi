# v0.29.1 — 素材一键导出 + 缩放/菜单/上传体验修复

> 用户诉求：① 增加「一键导出当前素材」按钮，生成包含完整命名文件的 zip，
> 且编码在 Windows / macOS 都能通用；② 设置缩放只改变桌宠大小，右键菜单保持
> 1.0 尺寸；③ 缩放应以中心为锚点，当前会向某个顶点偏移；④ 上传图片按钮太小，
> 高度要占满整行；⑤ 右键菜单移除「打开聊天 / 待办 / 提醒中心」，双击宠物作为
> 打开主界面的唯一入口；⑥ 主界面（聊天窗）支持调整窗口大小。2026-11-19。

## 目标

- 素材可以整包带走：导出的文件名保持规范英文命名，解压即用，跨平台不乱码。
- 宠物缩放与菜单解耦：缩放只影响形象，菜单永远按 1.0 设计尺寸渲染。
- 缩放视觉锚点从右下角改为窗口中心，放大/缩小不再"往角上跑"。
- 补齐上一轮计划中未落地的两项：右键菜单精简、聊天窗可缩放。
- 素材页的每状态「上传」按钮放大到整行高度，降低点击难度。

## 功能清单

1. **一键导出当前素材**（素材页右上角主按钮）：
   - 有用户素材 → 导出 `{appData}/pet-assets/` 中所有状态机可识别的文件，文件名原样保留
     （`happy.png` / `happy_001.png` / `happy_2.webp`）；
   - 没有用户素材 → 导出 10 张内置 SVG（`idle.svg` … `sleep.svg`），作为默认模板；
   - zip 落在 `{appData}/exports/mochi-pet-assets-<YYYYMMDD-HHmmSS>.zip`，导出后自动 reveal。
2. **右键菜单精简**：移除「打开聊天」「待办」「提醒中心」三项；双击宠物仍是打开主
   界面的唯一入口，菜单只保留番茄钟、站立提醒、设置、隐藏、调试、退出。
   同时删除对应 i18n key，未确认提醒/待办数量不再在宠物窗查询。
3. **菜单尺寸与宠物缩放解耦**：打开菜单前把宠物窗临时扩到至少 168×340 逻辑 px
   （只向上、向左右对称扩，形象在屏幕上不动），关闭菜单后恢复原尺寸与位置。
   菜单因此始终按 150px / 13px 的默认设计尺寸渲染，不再被 `100vw` 压扁。
4. **缩放中心锚点**：`apply_pet_scale` 改为保持窗口中心不动
   （`x += Δw / 2`、`y += Δh / 2`），替代原右下角锚点。
5. **聊天窗可缩放 / 拖动修复**：`resizable: true` + WebView 内八向透明热区
   （4px 边 / 12px 角），按下调用 `startResizeDragging`；标题栏 Tab 在窄窗口下
   改为横向滚动，不挤压关闭钮。同时补上 `core:window:allow-start-dragging` 权限——
   v0.23.1 的自绘标题栏拖动因该权限不在 `core:window:default` 里而一直静默失败
   （Promise 被 `.catch` 吞掉），本次修复后拖动才真正可用。
6. **每状态上传按钮放大**：`align-self: stretch` + `min-height: 32px`，与标题行同高；
   配色改为实心主色，和「选择图片」按钮同一视觉层级。
7. **补接 v0.29.0 自动贴边**：`maybe_auto_dock` 此前从未被调用（几何函数、开关、
   还原路径都写好了，但拖拽收尾没接线），本次接到 `snap_pet_to_edges` 末尾，
   自动躲藏/唤回功能才真正生效；顺手清掉 `restore_from_peek` 的未使用变量。
8. 版本对齐 `0.29.1`（package.json / Cargo.toml / tauri.conf.json）。

## 设计取舍

1. **菜单不引入第二个窗口**：独立菜单 WebView 虽然能彻底脱离宠物窗尺寸，但要新增
   窗口声明、capability、跨窗口 IPC 与焦点管理；而"临时扩窗 + 关闭还原"只动几何，
   复用现有自绘菜单。扩窗方向选"向上 + 左右对称"，因为形象是水平居中、贴底布局，
   这样扩完窗口后形象在屏幕上的像素位置完全不变。
2. **不把宠物窗的最小尺寸永久抬高**：固定最小窗口会让 0.2× 时宠物悬在窗口中间，
   贴边躲藏只留一条时会露出透明空白（v0.29.0 的 peek 语义被破坏）。临时扩窗只在
   菜单生命周期内生效，不影响贴边/穿透。
3. **导出"生效文件"而不是整个目录**：只收状态白名单内的文件，与运行时
   `listVariants` 的语义一致；中文名/未知状态本来就不会被状态机使用，导出它们只会
   制造"为什么另一台机器不生效"的困惑。
4. **用户素材优先、内置兜底**：用户目录只要有可识别素材，就不再混入内置图——与
   v0.23.0 "用户配过图就全面替换默认形象"的规则保持一致。
5. **zip 条目名保持纯 ASCII**：状态代码与扩展名都在白名单内，ASCII 在 Windows
   资源管理器与 macOS 归档实用工具中按同一字节解释，不需要赌系统代码页；
   zip crate 也不需要对非 ASCII 名做额外编码声明。
6. **缩放用中心锚点**：右下角锚点在放大时会让形象向左上移动，用户感知为"往顶点
   偏移"。中心锚点让窗口中心不动；形象水平居中、贴底，因此视觉上围绕自身缩放。
7. **聊天窗缩放走 `startResizeDragging`**：`decorations: false` 没有系统边框，
   前端铺透明热区把缩放交还系统，比自己在 JS 里算尺寸更稳（多屏/DPI 由 OS 处理），
   也不需要额外窗口权限（`core:window:default` 已包含该命令）。

## 踩坑与解决

1. **`ResizeDirection` 不是导出类型**：`@tauri-apps/api/window` 只在方法签名里使用
   该字面量联合，直接 `import type` 会 TS2459。改为本地声明同形字面量类型。
2. **扩窗是异步的，菜单位置会先按旧视口夹紧**：`prepare_pet_menu` 返回后 WebView
   的 `innerWidth/Height` 可能还没更新。ContextMenu 增加 `viewport` 状态与
   `resize` 监听，尺寸变化后重新 `clampMenuPosition`。
3. **右键请求竞态**：扩窗结果回来前用户可能已点别处。用 `menuRequestRef` 序号
   作废旧请求；作废分支主动调用 `restore_pet_menu`，避免窗口停在扩大态。
4. **扩窗后的坐标换算**：新窗口左上角相对旧窗口移动了 `(dx, dy)`，屏幕同一点在
   新视口中的坐标是 `oldClient - (dx, dy)`——由 Rust 返回逻辑像素位移，前端只做减法。
5. **聊天窗顶部 4px 热区会遮住标题栏拖动**：热区放在 header 之外、只占窗口最外圈，
   标题栏主体仍由 `dragWindow` 接管；窄窗口下 Tab 横向滚动，避免换行挤压关闭钮。
6. **`core:window:default` 不含拖动/缩放命令**：v0.23.1 的标题栏拖动注释写错了——
   默认权限集只含查询类命令，`startDragging` 必须显式授权；由于调用处 `.catch`
   静默，表现是"能点但拖不动"。本次在 capability 中补两条 allow 权限。
7. **自动贴边死代码**：v0.29.0 提交里 `maybe_auto_dock` 没有调用点，cargo 的
   `never used` 警告就是证据；本次接到拖拽收尾的吸附流程后，躲藏/唤回链路才闭合。
8. **程序性移动会被拖拽状态机误判**：缩放、菜单扩窗/还原都调用 `set_size` /
   `set_position`，产生的 `Moved` 会被当成"用户抓住宠物"，400ms 后还会触发贴边。
   给 `DragMotion` 加 300ms 抑制窗（并清空采样/复位握持广播），三类操作都先标记再动窗口。
