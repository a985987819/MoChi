# v0.25.0 — 宠物大小滑杆 + 高分屏/混合双屏保障

> 用户诉求："用进度条的形式控制宠物大小，每 0.1 一档，最低 0.2 最高 2，支持高分屏，
> Mac 以及 4K+2K 双屏都正常显示"。2026-11-19。

## 功能清单

1. **滑杆连续控制**：设置页宠物大小从三档下拉改为滑杆——0.2×~2.0×，0.1 一档
   （19 档），实时预览（每跨一档即时广播 `petScaleChanged`，Rust 即时改窗口尺寸，
   最多 19 次广播）；落盘 350ms 防抖一次。
2. **高分屏 / 混合双屏保障**（代码核查 + 一处真实修复）：
   - 窗口尺寸走 **逻辑像素**（`LogicalSize::new(220×scale, 260×scale)`）——Retina
     / 4K / 2K 的物理像素由系统按各自 scale factor 换算，跨屏移动窗口不变形；
   - **命中检测 DPI 修复**（真实 bug）：唤回轮询用 `primary_monitor` 的 scale
     factor 计算命中余量——混合双屏下主屏与窗口所在屏的 factor 不同，余量会
     偏大/偏小。改为 `current_monitor` 优先、primary 兜底。
   - 右下角锚点 + 屏内 clamp 都在物理像素域，缩放后位置语义不变。
3. 设置持久化：normalize 夹紧 [0.2, 2] 并量化到 0.1（`Math.round(n*10)/10`，
   避免 `12 * 0.1 = 1.2000000000000002`）；非法值回落 1。

## 设计取舍

1. **量化在 normalize 而非滑杆**：滑杆 step=0.1 已保证拖动档位，normalize 再量化
   一道防"手改 settings.json / 旧数据迁移"的非档位值——存储永远干净。
2. **`Math.round(n*10)/10` 而非 `round(n/0.1)*0.1`**：后者会产生
   `1.2000000000000002`（浮点乘法误差），前者是精确的十进制一位小数。
3. **广播与落盘分离**：拖动要 live 预览（窗口跟着滑杆变大变小），写盘要防抖
   （19 次磁盘写没有意义）——两条通道各按各的节奏。
4. **高分屏不做额外处理**：窗口尺寸与 CSS 全部逻辑像素，物理像素交给系统换算
   ——这是"保证正常显示"的正确姿势；唯一真实 bug（命中检测用主屏 DPI）已修。
