# v0.27.0 — 会话保留修复 + 宠物流式气泡

> 用户诉求：① "聊天用户会话会丢失，修复"；② "接入 API key 之后（优先 DeepSeek
> 官方 key）它就是一个完整的 agent，可以保留历史会话（默认只存在一个会话记录，
> 注意上下文控制）"；③ "宠物的话用流式传输进行展示"。2026-11-19。

## 根因（会话丢失）

两层叠加：
1. **用户消息从不落库**：runAgent 只持久化 assistant/tool 消息——`buildMessages`
   里的当前输入从未进 SQLite。重启后对话只剩麻薯的 assistant 消息，用户说过的话
   全部消失。
2. **未配置 Key 的对话完全不落库**：本地知识库路径（answerLocally）只更新 UI
   state，按 learning/04 的"当场可查"设计刻意不持久化——重启后凭空消失。

## 功能清单

1. **用户消息落库**：facade.runTurn 在 loadRecent **之后**追加
   `appendUserDeduped(userInput)`——次序关键：先读历史再追加，本轮上下文才不会
   把当前输入包含两遍（历史尾 + 当前输入）。重试重发同一输入由去重跳过。
2. **离线路径落库**：本地知识库问答的用户消息与回答都持久化（原"当场可查"设计
   被用户诉求覆盖）；未连接大模型的引导话术（静态模板）仍不落库（落库只会污染
   上下文）。
3. **展示历史扩容**：聊天窗展示 24 → 50 块——「保留历史会话」的 UI 侧；发给模型
   的上下文仍由 trimWindow 4000 token 预算裁剪（**展示与上下文控制解耦**）。
4. **DeepSeek 完整 agent 核查**：官方 API（api.deepseek.com）+ deepseek-chat 工具
   调用链路已在 v0.4.0 起打通；单会话（sessions.id='main'）+ 上下文预算
   （4000 tok + 成块裁剪）已是既定设计——本轮核查确认无需改动。
5. **宠物流式气泡**：回复流式期间，宠物头顶气泡实时展示尾部增量（300ms 节流、
   尾部 80 码点 + Markdown 轻剥离 + 前导省略号）；done 后进入 4 秒收尾淡出。
   替代 P1-01 的"仅隐藏窗口时发完成摘要"——流式全程展示，聊天窗可见与否不再影响。

## 设计取舍

1. **次序即正确性**：用户消息必须在 loadRecent **之后**落库——先追加会让
   buildMessages 的历史尾与当前输入重复（模型看到同一句话两遍）。
2. **重试去重在 Store**：ChatTab 的失败重试会重发同一输入；appendUserDeduped
   比"UI 层记住上次"可靠（跨窗口/重启都成立）。代价：连续两条一模一样的用户
   消息只留一条——罕见的误伤，换取重试路径的干净。
3. **流式气泡与暖心气泡共存**：TimedBubble 的 last-wins 状态机天然支持——流式
   期间点宠物弹出暖心句会覆盖流式文本（用户主动行为优先），流式下一拍又会夺回
   （轻微闪烁，可接受）。
4. **引导话术不落库**：静态模板进上下文只会浪费预算并让模型复读话术。
