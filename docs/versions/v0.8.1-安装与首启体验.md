## 设计取舍

1. **单语言而不是"中文优先"**：`languages` 数组的行为是"跟随系统语言，匹配不到用第一个"。
   保留 English 会让英文 Windows 装出英文安装器。产品定位是中文，直接单语言最没有歧义；
   将来要做英文版，改回数组并打开 `displayLanguageSelector` 即可（一行配置）。
2. **不做自定义 NSIS 模板改向导页文案**（第二次会话修正）：最初以为「Tauri 的欢迎页/
   完成页文案写死在 `installer.nsi` 里，要改必须整份复制模板」。实际读渲染模板发现：
   Tauri 把 hooks 文件 include 在「MUI2 之后、所有页面宏之前」，而 MUI2 的页面宏是在
   `!insertmacro MUI_PAGE_*` 时才读取 `MUI_WELCOMEPAGE_TEXT` 等定义——所以 hook 文件里
   两行 `!define` 就能覆盖欢迎页/完成页正文，不需要复制几百行模板（Tauri 升级会漂移）。
   代价：这两条是静态文案，不随系统语言变化——与取舍 1「强制简中」自洽，反而消除了
   语言回退的不确定性。模板自己的两个勾选框（创建桌面快捷方式 / 运行 Mochi）原样保留。
3. **引导放在聊天窗内做覆盖层，不做独立窗口/路由**：少一个 WebView 就少一套生命周期、
   IPC 与焦点问题；而且「去配置 Key」可以直接切到设置 Tab，形成闭环。
4. **首启自动弹窗而不是等用户发现**：「双击宠物打开聊天」没有任何视觉暗示，新用户大概率
   永远不知道。延迟 1.2s 是为了让麻薯先在角落出现，用户先建立"这是个会动的小东西"的印象。
5. **`onboardingDone` 放 settings 而不是 localStorage**：跟着应用数据走，重装/升级后仍然记得；
   且设置页回看引导 = 把它置回 false，零额外状态。
6. **刻意不提供"跳过且不再显示"**：新用户第一次关窗很可能只是切窗口，不该被判定为"看过了"。
   宁可多讲一次；如果后续觉得打扰，按施工单 P1-09 加一个"以后不再自动显示"的小字链接。

## 踩坑与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| hooks 文件中文乱码风险 | Tauri NSIS 模板是 `Unicode true`，脚本按 UTF-8 解析；无 BOM 时 NSIS 按 ANSI 处理中文 | 用 Node 给 `.nsh` 加 UTF-8 BOM（`ef bb bf`），并在文件头注释里写死这条约束 |
| 无法在沙箱里跑完整 `tauri build` 验证 | `vcvars64.bat` 内部调 `reg.exe` 被安全策略阻断 → `cl.exe` 环境不全 → `vswhom-sys`/`libsqlite3-sys` 编译失败 | 改用「`makensis` 单独编译 + 静默安装」做端到端验证：构造最小 `.nsi` 引入真实 hooks，编译通过；`/S` 安装后读取产物，确认 UTF-16LE 中文无乱码。完整打包留给用户在真实终端执行 |
| 编译验证时 `!include "E:/..."` 报 could not find | NSIS 的 `!include` 不接受正斜杠绝对路径（`File` 命令可以，预处理指令不行） | 用 awk 脚本文件生成反斜杠 include 行——直接在 shell 里写 `E:\\projects` 会被 Git Bash 的参数转换吃掉反斜杠，写成脚本文件绕开 |
| 旧渲染模板里没有 hooks include 行 | `target/release/nsis/x64/installer.nsi` 是 v0.8.0 时代的产物，`installerHooks` 是 v0.8.1 才加的配置；模板里 `NSIS_HOOK_*` 全是 `!ifmacrodef` 守卫调用，未注入时静默跳过、不报错 | 编译验证时在 `!include MUI2.nsh` 之后手工插入 include 行模拟真实渲染顺序；完整构建后复核新渲染模板里 include 是否由 bundler 注入 |
| `MochiPlaceholder` 放在 `<h1>` 里会断行 | 该组件根节点是 `display:block` 的 `<svg>` | 标题去掉内联 SVG，头像改用 `assets/pet/idle.svg` 的 `<img>` |
