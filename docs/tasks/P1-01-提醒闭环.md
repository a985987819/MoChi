# P1-01 提醒闭环：周期提醒 + 待办到期

- **状态**：claimed: workbuddy-claude（2026-11-17）
- **优先级**：P1（功能有了但没闭环）
- **依赖**：需要一次 SQLite 迁移 + 工具层契约变更
- **涉及文件**：`src/services/db.ts`（DDL）、`src/services/reminders.ts`、`src/services/todos.ts`、
  `src/agent/tools/reminder.ts`、`src/agent/tools/todo.ts`、`src/pages/chat/PomodoroTab.tsx`、
  `src/pages/chat/TodosTab.tsx`

## 背景（两个半成品）

1. **自定义提醒不支持周期**：`src/agent/tools/reminder.ts` 里直接对模型说
   "每天/每周 v1 暂不支持"。而"每天吃药""工作日喝水"是这类功能**最主要**的用法。
2. **待办有 `due` 却没人用**：`todos.due` 是**自由文本**（`用户原话或 ISO 日期`），
   UI 不填写、调度器完全不读 todos。所以"待办"现在只是清单，到期不会响。

## 目标

- 提醒支持 `repeat`：`none | daily | weekdays | weekly`；触发后自动排下一次；
- 待办增加结构化到期时间 `due_at`（epoch ms），到点走**同一条提醒通道**（`kind: "todo"`）；
- 两者都能在 UI 里设置与修改，工具层也能创建（自然语言入口）；
- 错过多轮周期（关机两天）时**只提醒一次**并跳到下一个未来时刻，不补发历史。

## 数据模型建议

```sql
-- reminders 增列
ALTER TABLE reminders ADD COLUMN repeat TEXT NOT NULL DEFAULT 'none';  -- none|daily|weekdays|weekly
ALTER TABLE reminders ADD COLUMN series_id TEXT;                       -- 同一串周期提醒的分组
-- todos 增列（保留原 due 文本，兼容旧数据/模型输出）
ALTER TABLE todos ADD COLUMN due_at INTEGER;
```

迁移必须**幂等**（`ensureSchema` 每次启动都跑）：用 `PRAGMA table_info` 判断列是否存在再 `ALTER`，
不要依赖 `ALTER ... IF NOT EXISTS`（SQLite 不支持）。

## 关键设计点

- **下一次怎么算**：纯函数 `nextOccurrence(fromMs, repeat, hour, minute)`，返回 > now 的下一个时刻。
  `weekdays` 要跳过周六周日；`weekly` 保持星期几；全部按**本地时间**算，并注意夏令时（可用
  `Date#setDate` 逐日推进而不是 `+86400000`，后者跨 DST 会偏一小时）。
- **触发语义**：认领（`status='fired'`）与排下一次（插入新行或更新同一行）必须在**同一个事务**里，
  否则崩溃会出现"重复提醒"或"漏一次"。建议插入新行 + `series_id` 分组，保留历史。
- **错过补发**：`nextOccurrence` 循环推进直到 > now；只交付一条。
- **工具层契约**：`create_reminder` 增加 `repeat` 参数并在描述里说明取值；`add_todo` 增加 `due_at`。
  模型可能给"明天九点"这种相对时间 → 由工具层解析（现有 `reminder.ts` 里已有时间解析逻辑，复用）。
- **待办到期提醒的正文**：用待办标题 + "到期了"；完成后（`done=1`）不再提醒。

## 验收标准

- [ ] `nextOccurrence` 单测：daily 跨日、weekdays 跳周末、weekly 保持星期、跨 DST 不偏、
      错过 3 天只返回 1 个未来时刻。
- [ ] 迁移幂等：连续两次 `ensureSchema` 不报错（单测用内存 SQLite）。
- [ ] 端到端（可脚本化）：插入一条 `repeat='daily'` 且已过期的提醒 → 只弹一次 →
      DB 里出现下一天的 active 行。
- [ ] UI：提醒区显示"每天 09:00"这类描述；待办可设到期时间。
- [ ] 文档：`docs/learning/08` 补充"周期提醒的时区与补发"一节。

## 坑

- **不要用 `setInterval` 记时**：现有调度以时间戳为准（`fire_at <= now`），周期提醒必须沿用，
  否则休眠/重启就错。
- **不要动 `status` 枚举**：`CHECK (status IN ('active','fired','cancelled'))` 是既有约束，
  周期提醒靠"新行 + series_id"，不要引入第五种状态。
- 时区：`fire_at` 存 UTC 毫秒，但**周期的"每天 9 点"是本地时间**，排下一次时要用本地时间算再转 UTC。
