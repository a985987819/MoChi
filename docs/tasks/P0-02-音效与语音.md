# P0-02 音效与语音朗读

- **状态**：open
- **优先级**：P0（缺"有声"这一整块感知通道）
- **依赖**：无（音效）；TTS 部分需先与用户确认方案
- **涉及文件**：`src/services/notifications.ts`、`src/services/alerts.ts`、`src/pages/pet/PetApp.tsx`、
  `src/pages/chat/SettingsTab.tsx`、`src/services/settings.ts`（新增开关）、新增 `src/services/sound.ts`

## 背景

全应用**零声音**：点击无反馈音、提醒只有视觉与系统通知、模型回复也不朗读。
视觉提示依赖用户"正好在看屏幕"，而这恰恰是桌宠最不该假定的前提。

## 目标（分两档，先做第一档）

**第一档 · 音效（必须做）**

- 点击宠物：极轻的"啵"；
- 提醒触发（站立/番茄/自定义）：一声柔和的提示音，可区分类型更好；
- 设置里可关、可调音量（默认建议：开，音量 30%）；
- **免打扰时段内不出声**（与 `services/quiet-hours.ts` 联动，别绕开它）；
- 无素材依赖：用 Web Audio 合成短音（正弦 + 快速衰减包络即可），避免为两声"啵"引入音频文件。

**第二档 · 语音（先决策再写）**

- 朗读助手回复（TTS）。两条路线：
  - Web Speech API（`speechSynthesis`）：零依赖、WebView2 支持、音色一般、可能依赖系统语音包；
  - 系统 TTS（Windows SAPI / macOS `say`）经 Rust 调用：音色好，但要写平台代码 + 权限。
- 建议先用 Web Speech API 做原型，能接受再考虑系统级。

## 非目标

- 不做语音输入（ASR）：需要录音权限与云服务，隐私成本高，另立项；
- 不做环境音/背景音乐。

## 设计建议

```ts
// src/services/sound.ts（新增）
export function playClick(): void;                 // 首次调用时懒创建 AudioContext
export function playAlert(kind: "standup" | "pomodoro" | "reminder"): void;
export function setSoundEnabled(enabled: boolean, volume: number): void;
```

- **懒创建 + 失败静默**：`new AudioContext()` 在部分环境会抛/挂起；失败一次后就标记不可用，
  不要每秒重试，也不要让音频问题影响提醒本身。
- **自动播放策略**：点击音天然有用户手势，没问题；提醒音可能在无手势时播放，
  WebView2 通常允许，但要有"播不出也不报错"的兜底。
- **播放位置**：宠物窗是常驻宿主，提醒音放这里播（提醒窗可能正在动画中重建）。
  触发点选 `state://app-alert-changed`，或直接在 `StandupService.fire()` / `PomodoroService.queueAlert()` 里调。
- **去抖**：连续多条提醒（例如休眠合并后的汇总）只响一次。

## 验收标准

- [ ] 设置项落盘 + `normalize` 夹紧（音量 0~100），老配置补默认；
- [ ] 关闭开关后**不创建 AudioContext**（可单测：注入假的 AudioContext 工厂，断言调用次数）；
- [ ] 免打扰时段内 `playAlert` 直接 return（单测）；
- [ ] 真机：点击有极轻反馈音、提醒有声、静默时段无声、音量调到 0 等于静音（**需用户本人听感确认**）；
- [ ] 版本文档写清"为什么合成音而不是打包音频文件"。

## 坑

- macOS 上 `AudioContext` 在后台窗口可能被挂起；宠物窗常驻可见，通常没事。
- 不要用 `new Audio()` 播放 data URL（体积与解码开销）；用 `OscillatorNode` + `GainNode`。
- 提醒音不要把 `notificationsEnabled`（系统通知开关）当唯一条件——那是另一个通道。
- 若做 TTS：朗读长回复要能打断（新消息到达 / 用户点停止），否则会堵住耳朵。
