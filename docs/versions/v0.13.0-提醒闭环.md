# v0.13.0 — 提醒闭环：周期提醒与待办到期

## 目标

P1-01。两个"半成品"：

1. **自定义提醒不支持周期**——工具里直接对模型说"每天/每周 v1 暂不支持"，而"每天吃药""工作日喝水"
   正是这类功能最主要的用法。
2. **待办有 `due` 却没人用**——`due` 是自由文本，UI 不填、调度器不读，所以待办只是清单，到期不会响。

本版让两者都能真正"到点说话"，并且都走同一条投递链路（原生提醒队列 + 系统通知 + 聊天历史）。

## 功能清单

- [x] 提醒支持 `repeat`：`none | daily | weekdays | weekly`，触发后自动排下一次。
- [x] 待办支持结构化到期时间 `due_at`，到点弹一次「待办到期」提醒（只弹一次）。
- [x] 工具层同步：`create_reminder` 增加 `repeat`；`add_todo` 增加 `due_at`（允许过去 = 逾期）。
- [x] UI：待办页可设「到点提醒」，列表显示到期时间（今天/明天相对词，逾期变红）；
      番茄钟提醒列表显示「每天 / 工作日 / 每周」。
- [x] 数据库幂等迁移（旧库自动补列，新库 DDL 同步）。
- [x] 版本对齐 0.13.0，安装包 `run_here/windows/Mochi_0.13.0_x64-setup.exe`。

## 文件级实现细节

### 周期推算（`src/services/recurrence.ts`，新增）

- `Repeat` 类型 + `REPEAT_VALUES`（工具枚举、UI 标签、DB 读回共用一份）+ `parseRepeat`（脏数据兜底）。
- `nextOccurrence(fireAt, repeat, after)`：
  - 按本地日历推进（`setDate`），**不用** `+86400000`——夏令时切换日会偏一小时；
  - 保留原 fire_at 的时分（"每天 9:00"永远 9:00）；
  - `weekdays` 跳过周六周日；`weekly` +7 天；
  - 结果**严格晚于** `after`（关机三天只补一次，落到下一个未来时刻）；
  - 迭代上限 1000 次，异常数据返回 `null` 而不是死循环。

### 数据层（`src/services/db.ts`）

- `reminders` 增 `repeat TEXT NOT NULL DEFAULT 'none'`、`series_id TEXT`；
  `todos` 增 `due_at INTEGER`、`due_notified_at INTEGER`。
- 新增通用 `ensureColumn(db, table, column, ddl)`：`PRAGMA table_info` 查列 → 缺失才 `ALTER`；
  ALTER 失败后再查一次（两个窗口可能同时开库，另一个已完成即视为成功）。
- 新库 DDL 直接包含这些列，所以"新建"与"升级"走同一条读路径。

### 提醒服务（`src/services/reminders.ts`）

- `Reminder` / `ReminderRow` 增加 `repeat` / `seriesId`；`create(text, fireAt, repeat)` 生成 `seriesId`。
- 新增 `scheduleNext(row, now)`：**插入新行**（同 text / series_id / repeat），下一次由
  `nextOccurrence` 从 `now` 之后算。
- 调用点有两处，缺一不可：
  - 普通交付成功后（`tick` 的认领循环里）；
  - **合并交付**时（`coalesceOverdue`）——否则一条"每天"的提醒会因为"睡了一夜被合并"而彻底消失。
- 新增 `scanTodoDue(now, generation)`：扫 `done=0 AND due_at<=now AND due_notified_at IS NULL`，
  用条件更新认领（`WHERE due_notified_at IS NULL`，`rowsAffected === 1` 才算抢到），
  然后走同一个 `showAppAlert` + 通知 + 历史；显示失败回滚标记，下一拍重试。

### 工具层

- `create_reminder`：新增 `repeat` 参数（enum），描述里删掉"v1 不支持周期"，改成
  "周期提醒请传 daily/weekdays/weekly，fire_at 传第一次触发时刻"。
- `add_todo`：新增 `due_at`（ISO）。新增 `parseDueAt` 与 `parseFireAt` 有一处刻意差异：
  **允许过去时间**——"昨天到期还没做"是待办要如实呈现的状态，拒绝它只会让模型把逾期任务
  硬塞成未来时间，信息反而失真。

### UI

- `TodosTab`：新增「到点提醒（可选）」`datetime-local`（空 = 只记清单）；`TodoRow` 展示
  `dueAt`（今天/明天用相对词，其余月日时分；逾期用主色）。
- `PomodoroTab`：提醒时间前加「每天 / 工作日 / 每周」标签。
- `chat.css`：`.todos-due`、`.todo-row__due--overdue`、`.pomo-reminder__repeat`。

## 设计取舍

**① 周期提醒插新行，不改原行**
保留触发历史（"确实提醒过三次"），并且让"错过多次只补一次"自然成立：下一次永远从 `now`
之后算，不需要记住"上次应该在哪一天"。

**② 待办到期不复用 reminders 表**
待办是用户清单，到期只是它的一个时间属性。把它塞进提醒表会出现两份数据互相打架
（改标题、改时间、完成状态都要同步）。用 `todos.due_notified_at` 做一次性认领，简单且幂等。

**③ 为什么 `due_at` 与 `due` 并存**
`due` 是"用户怎么说的"（展示价值），`due_at` 是"机器能算的"（调度价值）。历史数据与模型
输出的自由文本不必清洗，新增的 `due_at` 只对"确实是时间点"的待办生效。

**④ 补发策略：只补一次**
关机三天再开机，daily 提醒只弹一次（内容不变，时间敏感度已经过了），然后落到明天的正常时刻。
逐条补发会把"提醒"变成"惩罚"。

**⑤ 迁移不用版本号表**
沿用项目既有风格：先查列在不在，不在就加。版本号表要维护"执行到第几号"，在"单人 + 多窗口"
场景里反而多一个不一致源。

## 踩坑与解决

### ① 合并交付会吃掉周期提醒

v0.11.0 的 `coalesceOverdue` 把积压提醒一次性标成 fired + acknowledged。如果只在普通交付路径
排下一次，那些被合并的"每天"提醒就再也不会有下一次。修法：合并路径里对每个被认领的
repeat 行也调 `scheduleNext`。

### ② 待办提醒的"只弹一次"要靠条件更新

`SELECT` 与 `UPDATE` 之间可能被另一拍（或另一个窗口）抢到，所以认领必须写成
`UPDATE ... WHERE due_notified_at IS NULL` 并检查 `rowsAffected`——和提醒表认领同一套思路。

### ③ 时间解析的两套语义要说清

`parseFireAt` 拒绝过去时间（提醒"迟到"没有意义），`parseDueAt` 允许过去（逾期待办是合法状态）。
两个函数放在各自工具文件里，注释互相点名，避免以后有人"统一"掉。
