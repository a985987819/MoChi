## 目标

建立 i18n 基建（事实源 + 类型约束 + useT + 语言项 + 扫描脚本），首批界面完成双语化。

- `src/shared/i18n/`：`zh-CN.ts`（唯一事实源，81 个 key）+ `en.ts`
  （`satisfies Record<MessageKey, string>` 类型级对齐——加 key 不翻译直接编译报错）
  + `core.ts`（t/插值/locale 状态/resolveLocale/installLocaleWatcher）
  + `react.ts`（useT，useSyncExternalStore 订阅）。
- 设置页「语言 / Language」三档：跟随系统（默认）/ 简体中文 / English；
  切换**不需要重启**（各窗口 installLocaleWatcher 监听 settingsChanged）。
- 首批迁移（完整单元）：Tab 栏、提醒中心、待办、番茄钟、提醒弹窗（alert 窗）、
  宠物右键菜单、共享组件（Loading/MochiPlaceholder aria）。
- `scripts/check-hardcoded-zh.mjs`（`pnpm lint:i18n`）：扫描 CJK 字符串字面量，
  615 处存量全部建档（三类：UI 欠账 / 模型输入刻意中文 / 服务层错误文本）；
  **未建档的新增硬编码会让脚本退出非零**——防回归。

## 设计取舍

1. **不引 i18next**（任务单明确）：需求全集 = 两字典 + 插值 + 切换 + 系统检测，
   中文无复数——ICU/命名空间全用不上，80 条文案付不起那个心智。
2. **英文复数用措辞绕开**："未完成 · N" → "Open · N"，"N 条待确认" → "N to
   confirm"——简单函数（t + 模板）就能扛住当前文案形态。
3. **Agent 层文案刻意不迁移**（扫描建档的②类）：system prompt、工具描述、
   工具错误回传都是**发给 LLM 的协议文本**——模型输出以中文为主，输入语境
   切英文只会降低对话质量。pet-chatter 的 144 条随机文案同理（那是文案创作，
   机械翻译只会更差，任务单原文）。
4. **服务层错误文本留作下一批**（③类）：它们会进 UI，但要先把散在各服务的
   错误文案集中到 error-text 模式再统一走 t——散着翻等于把债务复制一遍。
5. **缺 key 三级回落**：当前字典 → zh-CN → key 本身。类型系统理论上杜绝缺 key，
   回落链防的是"绕过类型的运行时拼接"。
6. **扫描脚本存量不挡 CI、增量挡**：615 处是已知债务（建档可见）；新出现的
   未建档硬编码立即失败——迁移是收敛过程，回归是事故。

## 踩坑与解决

- 正则批改组件时把 Loading 的 `label` prop 改名成了内部变量、又忘了给
  MochiPlaceholder 补 useT 调用——tsc 双双抓出。教训：机械替换之后必须
  `pnpm check` + 看一眼 diff，脚本不是免检通行证。
- 扫描初版把 JSDoc 注释里的中文也算进去（注释是文档不是 UI）——先剥注释
  再匹配字符串字面量。
