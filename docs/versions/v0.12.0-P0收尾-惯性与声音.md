## 文件级实现细节

### Rust（`src-tauri/src/lib.rs`）

- `DragMotion` 增加 `samples: VecDeque<(i32, i32, Instant)>`（最近 8 个、≤150ms）与 `inertia: bool`。
- 常量：`INERTIA_MIN_SPEED = 250px/s`（低于它不滑）、`INERTIA_FRICTION = 0.88`/帧、
  `INERTIA_STOP_SPEED = 40px/s`、`INERTIA_MAX_STEP = 120px`（单帧限幅）、`INERTIA_MAX_MS = 600`、
  `INERTIA_STEP_MS = 16`。
- `drag_velocity(&samples) -> Option<(f64, f64)>`：首尾位移/时长；<2 样本或 <16ms 返回 `None`。
- `inertia_step(pos, vel, dt, size, area) -> (pos, vel, done)`：纯函数，摩擦衰减 + 边界清零 +
  限幅 + 停止判据。
- `start_inertia(app, velocity)`：独立线程按 16ms 步进，位置变更经 `run_on_main_thread` 执行；
  `static INERTIA_GENERATION: AtomicU64` 每开始一次 +1，线程自查世代号决定是否继续。
- `finish_inertia(app)`：清 `inertia`/`samples` 后调 `snap_pet_to_edges`，并且**也排回主线程**，
  保证排在最后一批 `set_position` 之后。
- `WindowEvent::Moved`：`motion.inertia` 为真时直接 `return`（惯性期间窗口是自己动的）。
- 松手分支：`Some(velocity)` 且速度 ≥阈值 → `start_inertia`，否则 `snap_pet_to_edges`。
- `ui://drag-pet` 监听：先 `INERTIA_GENERATION + 1` 并清 `inertia`，再 `start_dragging`。

### 音效（`src/services/sound.ts`，新增）

- `planFor(kind)`：音符表（纯函数）。click 880Hz/70ms/0.05；standup 660→880；
  pomodoro 523→659→784；reminder 740→988。
- `clampVolume(percent)`：0~100 → 0~1，异常值回落 0.3。
- `configureSound({ enabled, volumePercent, quietHours })`：关开关时 `close()` 并置空。
- `play(kind)`：懒创建 `AudioContext`（`globalThis` 取构造器，失败一次即永久标记不可用）；
  `OscillatorNode` + `GainNode`，起音 8ms 指数上升、按音符时长指数衰减；每步 `try/catch`，
  单个音符失败不影响其它音符，更不影响提醒。
- `playClick()` / `playAlert(kind)`：对外两个入口。

### 接线

- `pet/main.tsx`：`syncStartupSettings` 里 `configureSound`（启动 + 设置变更都会走到）；
  新增 `settingsChanged` 监听重放；新增 `appAlertChanged` 监听播放提醒音（同一 id 只响一次）。
- `pet/PetApp.tsx`：`clickFeedback` 里 `playClick()`（与弹跳同属即时反馈，不等双击判定）。
- `chat/SettingsTab.tsx`：新增 `SoundSection`（开关 + 滑杆 + 说明）；`chat.css` 补 range 样式。
- `services/settings.ts`：`soundEnabled` / `soundVolume` 两个字段 + `normalize` 夹紧。

## 设计取舍

**① 惯性用干摩擦 + 撞墙即停，不用弹簧**
弹簧会有"回头"动作——桌宠被扔到屏幕边上又弹回来，观感很离谱。干摩擦 + 该轴速度清零，
符合"放在边上就该停在那儿"的直觉，也正好和 v0.10.0 的贴边吸附接上（惯性负责滑到附近，
吸附负责正好贴住）。

**② 为什么必须开线程**
现有原生节拍是 1s，做不出滑行。16ms 步进需要自己的线程；但它只活几百毫秒，滑完即退出，
不是常驻动画循环。

**③ 取消用原子世代号，不用通道/标志位**
用户重新抓起宠物时，`ui://drag-pet` 里 `INERTIA_GENERATION + 1`；滑行线程每帧对比自己的世代号。
比"发取消信号 + 等确认"简单，也不会出现两个滑行线程同时改位置。

**④ 音效合成而不是打包音频**
只有三种短音，打包 wav/mp3 要处理体积、采样率、仓库二进制；`OscillatorNode` 二十行解决，
而且音量/音高天然可调。听着不满意时改 `planFor` 里的 hz/ms 即可。

**⑤ 播放点集中在"提醒队头变化"**
如果在 `StandupService.fire()`、`PomodoroService.queueAlert()`、提醒调度里各写一句，
以后新增提醒类型必然漏一处。统一监听 `state://app-alert-changed`，按 `kind` 选音色，
并按 id 去重（重试不会放两遍）。

**⑥ 点击音不受免打扰影响**
免打扰的语义是"别用系统自动生成的东西打扰我"；点击是用户主动操作，静默它只会让人以为程序卡了。

**⑦ 音效默认开、TTS 默认关（后者待做）**
声音是"不看屏幕也知道发生了什么"的唯一通道，桌宠的提醒本来就假设用户没盯着它，
所以默认开、给一键关闭；而朗读会持续占用听觉，默认必须关。

## 踩坑与解决

### ① 惯性期间的 Moved 事件来自自己

`set_position` 会触发 `WindowEvent::Moved`。原逻辑把它当成"用户还在拖"→ 刷新静默窗口 →
拖拽永远不结束；或者被 `drag_transition(false, Some(0))` 判成"新拖拽"。修法：`inertia` 标记，
滑行期间整段忽略 Moved，抓起时清标记。

### ② 收尾贴边读到的是旧位置

`set_position` 是排到主线程队列执行的，滑行线程结束时主线程可能还没处理完最后几帧。
如果此时直接 `snap_pet_to_edges`（同步读 `outer_position`），会按旧位置算吸附。
修法：收尾也 `run_on_main_thread`，排在最后一批移动之后。

### ③ 测试字面量又缺字段（第二次）

`settings-debounce.test.ts` 里的 `const base: AppSettings = {...}` 手写全字段，加 `soundEnabled`
/`soundVolume` 后编译失败。**建议后续把这类构造改成 `{ ...defaultSettings(), 覆盖项 }`**，
避免每加一个设置项都要改测试。已记在任务板 P2-03 的注意事项里（同类问题）。

### ④ 音效的自动化验证只能做到"链路通"

听感无法脚本化。实际验证方式：用 CDP 包一层 `window.AudioContext` 计数（`ensureContext`
每次都从 `globalThis` 取构造器，所以能观测），派发一次真实鼠标事件，断言"创建了 1 个"；
再把 `soundEnabled` 置 false 并重发 `settings-changed`，再点一次，断言"创建 0 个"。
这能证明链路与开关都生效，但证明不了"好不好听"。
