# P1-03 语音朗读（TTS）

- **状态**：open（**需用户先决策方案**）
- **优先级**：P1（"能听见麻薯说话"是陪伴感的一大块，但成本与体验不确定性高）
- **依赖**：`P0-02` 已完成（音效通道与设置项已在位）
- **涉及文件**：`src/services/sound.ts`（复用配置）、新增 `src/services/tts.ts`、
  `src/pages/chat/ChatTab.tsx`（每轮回复结束后触发）、`src/pages/chat/SettingsTab.tsx`

## 背景

v0.12.0 补了音效（点击/提醒），但助手回复仍然只有文字。用户离开屏幕时，桌宠"说了什么"
完全没有感知通道。TTS 是这条链路的最后一块。

## 需要先决策（这一步不做就别写代码）

| 方案 | 优点 | 代价 | 备注 |
|---|---|---|---|
| Web Speech API（`speechSynthesis`） | 零依赖、WebView2 支持、立刻可用 | 音色机械、依赖系统语音包、中文音质参差 | 推荐先做原型 |
| 系统 TTS（Windows SAPI / macOS `say`）经 Rust | 音色更好、可控语速 | 平台代码、可能需要额外权限 | 二期 |
| 云端 TTS（如各家 API） | 音色最好 | 要 Key、要联网、隐私与成本 | **不建议**：与"离线可用"的产品气质冲突 |

## 目标（决策为 Web Speech 时）

- 助手回复**完整结束后**朗读（流式过程中朗读会结巴）；
- 可随时打断：新消息到达、用户点击宠物、窗口关闭 → 立即停止；
- 设置项：朗读开关（默认**关**，比音效保守）、语速、音色选择（系统提供的列表）；
- 超长回复只读前 N 字（建议 200 字）+ "其余在聊天窗"提示，避免念三分钟；
- 与免打扰时段一致：时段内不朗读。

## 实现建议

```ts
// src/services/tts.ts
export function configureTts(next: { enabled: boolean; rate: number; voiceName?: string }): void;
export function speak(text: string): void;   // 内部做长度截断 + 打断上一条
export function stopSpeaking(): void;
```

- 用 `speechSynthesis.cancel()` 打断，不要靠 `pause()`（各平台行为不一致）。
- 注册 `voiceschanged` 事件：Chrome/WebView2 首次 `getVoices()` 可能为空。
- 中文优先选 `zh-CN` 音色；没有则回落到默认并提示用户。

## 验收标准

- [ ] 开关关闭时**不调用** `speechSynthesis`（可注入假对象断言调用次数）。
- [ ] 超长文本截断逻辑有单测（纯函数 `trimForSpeech(text, limit)`）。
- [ ] 打断：连续两次 `speak()` 只念最后一条（真机确认）。
- [ ] 免打扰时段不朗读。
- [ ] 版本文档写清"为什么默认关"。

## 坑

- 朗读会与系统通知音/音效叠加，注意音量别把用户吓到；建议朗读音量独立于音效音量。
- macOS 的 `speechSynthesis` 在后台窗口可能被挂起，需要真机确认。
- 不要把模型返回的 Markdown 原样念出来：先去掉 `**`、代码块、链接（写个 `plainTextForSpeech` 纯函数）。
