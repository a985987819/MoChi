## 文件级实现细节

### 数据层

- `services/db.ts`：单例连接 + 幂等 DDL（sessions/messages/todos/memories，字段权威定义在 04 §3.1）；**选 TS 侧 ensureSchema 而非 config migrations**（教学透明 + 零配置 schema 风险，版本文档记录偏差）。
- `services/todos.ts`：add 返回 Promise（lastInsertId）；迁移逻辑（读 todos.json → INSERT OR IGNORE → 清空旧文件内容）。

### 记忆层（src/agent/memory/）

- `history-store.ts`：`loadRecent(blockCount)` 按**块**恢复（assistant+tool 组完整性）；`rowToMessage` 反序列化 toolCalls。
- `long-term.ts`：**"存了但查不到"防线 = remember 里落库与 retriever.upsert 绑定**（04 §4.1 闭环纪律）；索引内存重建（<10ms）。

### 检索层（src/rag/）

- `retriever.ts`：接口三件套（upsert/remove/search）+ meta 挂原始数据——v0.6.0 的 food 数据直接复用。
- `bm25.ts`：k1=1.5/b=0.75；IDF 用 Lucene 变体（恒正）；查询内去重；removeDocument 收缩空倒排链。

### 内核与 UI

- `core/window.ts`：trimWindow 至少保一块（全裁剪视为 bug）；防御：首条非 system 时原样返回。
- `core/context-builder.ts`：`buildInitialMessages` 泛化为 **buildMessages({history,...})**（层序 = 03 §2.1：system→记忆→历史→输入）。
- `core/agent.ts`：`persist?` 回调（v0.4.0 预留的同步点正式接线）。
- `facade.ts`：runTurn 并行取（裁剪历史 ∥ 记忆检索）→ buildMessages → persist 闭环；不再接收 history 参数。
- `ChatTab.tsx`：挂载 loadEntries（SQLite→UI，tool 明细并入 note）；listen `state://history-cleared` 重载。
- `SettingsTab.tsx`：MemoriesSection（查看/删除，04 §5 隐私规范落点）+ DangerZone（清空历史 confirm）。

### 依赖变化

- npm：+ `@tauri-apps/plugin-sql`；cargo：+ `tauri-plugin-sql`（sqlite）。

## 设计取舍

1. **协议原样落库**（tool_calls JSON 整存）：恢复即用、无信息损失；行宽代价由上下文层的窗口裁剪吸收，不影响存储层（04 §6）。
2. **记忆索引内存重建**：数据量小重建 <10ms，免索引持久化（04 §6 既定裁决）。
3. **DDL 走 TS 代码而非 conf migrations**：透明可读；schema 演进时加 ALTER 并同步文档。
4. **检索与 RAG 共用 Retriever**：一套代码两处收益——这是 04 的核心架构主张，v0.6.0 兑现。
5. **清空历史不动会话行**：sessions 表 v1 单会话，行保留便于 v2 多会话统计。

## 踩坑与解决
