## 设计取舍（Night 1）

1. **P0-02 防抖独立成文件**：settings.ts 顶层 import plugin-store，直接在里面写防抖
   就无法在 node 环境单测（vite.config.ts 测试纪律）。机制纯函数化 + settings.ts 5 行适配，
   比引入 vi.mock 更符合项目分层。
2. **P0-02 离散控件不防抖**：下拉/开关是单次事件，直存 + 广播；防抖只给字符级输入。
   blur/卸载时 flush 补齐防抖的「延迟落盘」代价。
3. **P0-03 授权集中在启动**：授权框是「预期内的打断」，放启动时；到点时刻只查权限。
   插件只暴露 granted 布尔值（没有 denied/not-asked 之分），未授权时同时给
   页面内请求 + 系统设置路径两条恢复路。
4. **P0-04 选 window-state 插件**：源码核实其内部跟踪 Moved + RunEvent::Exit 自动落盘
   （2.5.0 第 528-530 行），自己写保存逻辑等于重造；只开 POSITION——VISIBLE 会破坏
   chat「隐藏启动」设计。恢复后自做可见性校验（插件不校验多屏悬空）。
5. **P0-04 工作区查询下沉平台 API**：Tauri 2 的 Monitor 无「工作区」概念（只有
   size/position/scale_factor），避开任务栏必须 SPI_GETWORKAREA；用 windows crate
   （0.62 已在依赖树，不新增编译单元）+ `#[cfg(windows)]` 隔离，macOS 保持整屏算法。

## 踩坑与解决（Night 1）

| 问题 | 原因 | 解决 |
|---|---|---|
| `vsenv.cmd cargo check` 报找不到 Cargo.toml | 包装脚本固定 `cd /d %~dp0..` 到仓库根，而 manifest 在 src-tauri/ | 传 `--manifest-path src-tauri/Cargo.toml` |
| windows crate SystemParametersInfoW 编译错两处 | 0.62 签名：第 4 参是 `SYSTEM_PARAMETERS_INFO_UPDATE_FLAGS` 类型（非 Option）；`cast()` 应作用于指针而非 Option | `Some((...).cast())` + `SYSTEM_PARAMETERS_INFO_UPDATE_FLAGS(0)` |
| 测试箭头函数隐式返回 push 数值 | persist 签名要求 `void \| Promise<void>` | 箭头函数体加花括号 |
