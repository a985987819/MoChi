# v0.15.0 — 语音朗读 TTS（P1-03）

> 任务单：`docs/tasks/P1-03-语音朗读.md`。完成于 2026-11-17。
> 用户指令：TTS 用免费音源；云端方案不做。

## 目标

助手回复"说得出来"：回复完整结束后朗读，随时可打断，设置可控，免打扰时段静默。

## 方案决策（任务单"需先决策"的落点）

**Web Speech API（`speechSynthesis`）—— 免费音源**：

| 对比项 | Web Speech（选它） | 系统 SAPI/`say` 经 Rust | 云端 TTS |
|---|---|---|---|
| 依赖 | 零（WebView2 内置） | 平台代码 | Key + 联网 |
| 成本 | 免费 | 免费 | 按字计费 + 凭据面 |
| 离线 | ✓ | ✓ | ✗ |
| 音色 | 机械（系统语音包） | 较好 | 最好 |
| 跨平台 | 一套 API | 两套实现 | 一套 API |

用户指令"优先配置免费的音源"直接排除云端；Web Speech 零依赖一套代码双平台，
作为 v1 路线。音色机械是已知代价——用"默认关 + 可调语速/音色"消化。

## 功能清单

- 回复**完整结束后**朗读（`done` 事件之后、异常路径不读）；
- 可打断：发新消息 / 单击宠物（`ui://reset-standup` 广播复用）/ 关闭聊天窗 → `cancel()`；
- 设置项：朗读开关（默认**关**）、语速 0.5~2.0x、音色下拉（系统列表 + 自动中文优先）+ 试听按钮；
- 超长回复只念前 200 字 + "其余在聊天窗"提示；
- Markdown 纯文本化：代码块跳过、链接念文字、粗斜体/标题/列表/引用符去标记；
- 免打扰时段不朗读（与音效同一条礼貌规则）；
- 本地知识库回答（离线问答）同样朗读；离线引导文案不读（那是 UI 状态提示，不是对话）。

## 设计取舍

1. **为什么默认关**（任务单验收要求写清）：音效是短促提示音（预期内、可忽略），
   TTS 是把整段回复念出来——不问就把每轮对话念出声是打扰，比没有更糟。所以
   默认关，让用户主动开。这与音效"默认开"不矛盾：提示音的打扰成本和说话声
   不在一个量级。
2. **朗读音量独立（恒 1）**：不与音效音量混用一个滑条——把"点击哒声"和"人声"
   绑死会让调小音效的人听不见朗读。要更小声用系统音量。
3. **打断用 `cancel()` 不用 `pause()`**（任务单明确）：各平台 pause 语义不一致；
   且本项目场景里"被新内容取代"就该从头念新的，没有恢复旧朗读的需求。
4. **音色回落链**：指定名 → zh-CN → 任意 zh → 系统默认。WebView2/Chrome 首次
   `getVoices()` 常为空（`voiceschanged` 后才有），回落到默认而不是报错；设置页
   用订阅刷新下拉 + "没找到中文音色"的提示兜住认知。
5. **免打扰时段静默 TTS**：任务单明确要求。注意免打扰本来的语义只覆盖站立提醒
   （v0.10.0），这里把 TTS 作为第二种纳入静默的声音通道——朗读比弹窗更容易在
   深夜变成事故。
6. **`speaking` 守卫**：`stopSpeaking` 只在真的在朗读时才 `cancel`——配置初始化、
   开关切换这些高频路径不惊动合成器，也让测试里"配置动作"与"朗读动作"的调用
   计数彻底分开。

## 踩坑与解决

- **测试状态渗漏**：`config` 是模块级状态，"免打扰"用例设置的 `[当前小时, 下一小时)`
  静默窗口会渗进后面所有没显式覆盖 quietHours 的用例（表现为 speak 静默、cancel
  计数为 0）。修复：beforeEach 显式重置配置——新增 synth 未在朗读，重置触发的
  `stopSpeaking` 是空操作，不会污染调用计数。
- **TS 双向函数兼容性**：真实 `SpeechSynthesisUtterance.onerror` 的参数类型窄于
  通用错误记录签名，把它放进结构子集接口会让"真对象 → 子集类型"赋值报错。
  解决：接口不含 onerror，赋值经一次受控断言完成（只记录不转发，无类型损失）。
- **语速是浮点**：settings 的 `clampInt` 会把 1.5 取整——新增 `clampFloat`。
