# v0.14.0 — 提醒可见性（P1-02）

> 任务单：`docs/tasks/P1-02-提醒可见性.md`。完成于 2026-11-17。

## 目标

提醒"发出去"之后用户找得到"发过什么"：

1. 点系统通知 → 聚焦聊天窗并直达对应 Tab（提醒/待办/聊天）；
2. 新增**提醒中心**（「提醒」Tab）：进行中 + 历史三类状态 + 再次提醒；
3. 未确认提醒的角标：聊天窗 Tab 与宠物右键菜单显示一致的数量。

## 功能清单

- 通知点击路由：`onAction` 监听在宠物窗启动时注册，按通知标题前缀路由
  （⏰ → 提醒中心、📌 → 待办、其他 → 聊天）。
- 提醒中心 Tab（第六个 Tab，位于待办之后）：进行中（active，可取消）+
  历史（fired/cancelled 倒序分页，每页 20 行 + 加载更多）。
- 合并交付批次（v0.11.0 长休眠恢复）在历史里按 `batch_id` 聚合成一条
  「⏰ N 条提醒到点了」（`<details>` 原生展开，每条原文可单独再次提醒）。
- 「再次提醒」：+30 分钟（从点击时刻起算）/ 明天同一时间（原提醒的本地时分，
  明天的本地日历日期）。仅一次性提醒（repeat=none）显示——周期提醒的下一轮
  已自动排好，手动补会出现同一时段两条。
- 未确认角标：聊天窗「提醒」Tab 上（>0 才渲染，9+ 封顶）；宠物右键菜单
  「提醒中心 · N 条待确认」。两处数据源都是 `unacknowledgedCount()`（同一
  SQLite），变化节奏由 `remindersChanged` 广播对齐。

## 设计取舍

1. **通知点击用插件既有 `onAction`，不引第二个通知插件**。调研结论（插件源码
   v2.8.0 desktop.rs）：桌面端点击 toast 回报 `actionId="tap"` + 通知数据
   （含 title），且**只对监听器存在期间发出的通知回报**——所以注册点必须在宠物窗
   启动时、任何通知发出之前。平台限制：Windows 只有 toast 还在屏幕上时点击才
   回报，进了操作中心的历史通知点了没反应（系统行为）。
2. **按标题前缀路由而不是 Action Type 按钮**：Action Type 是移动端机制（桌面没
   按钮就不触发）；标题是应用自己定的稳定常量（⏰/📌 前缀），跨平台一致且零配置。
3. **提醒中心独立成 Tab，从番茄钟页迁出**：v0.7.0 把提醒列表寄在番茄钟页是当时
   没有更合适的宿主；有了历史与再次提醒后，「提醒中心」是独立心智单元（番茄钟
   是计时器，提醒是承诺）。任务单允许"或新 Tab"，采纳后者。
4. **批次判定只认 batch_id 不认"同一秒"**：调度循环里两条独立提醒可能恰在同一
   毫秒被认领（`Date.now()` 同值），按时间聚合会把它们误标成"合并交付"。加一列
   `batch_id` 的成本远低于历史列表撒谎的代价。
5. **角标一致性的实现**：SQLite 是单一事实源（两侧查同一个库），`remindersChanged`
   广播负责变化节奏；确认落库后调度器补发一次广播是关键——此前确认只写库不广播，
   聊天窗角标要等下一次提醒事件才会下降。
6. **分页按行计数**：合并批次理论上可被分页边界截断（前页尾部 + 后页头部各显示
   一部分）。实际单次合并批次 = 过期提醒条数（每条周期提醒只补一次，现实 ≤10 行），
   页长 20 行，概率极低；游标分页的复杂度不匹配收益，作为已知限制记录。

## 踩坑与解决

- `onAction` 的返回值是 `Promise<PluginListener>`，await 后直接得到监听器对象，
  卸载用 `listener.unregister()`（不是 tauri api event 的 `unlisten` 函数）。
- 测试 helper 里"后置展开默认 firedAt"会覆盖用例显式传入的 `firedAt`——
  默认值必须让位给显式参数（`"firedAt" in overrides` 判断）。
- 本会话浏览器运行时不可用（CLI 工作区所有权限制），Tab 栏宽度按盒模型算术
  核验（六 Tab + badge ≈ 338px < 480px 可用宽度约 344px），真机视觉走查留给用户。
