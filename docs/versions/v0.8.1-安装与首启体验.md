## 设计取舍

1. **单语言而不是"中文优先"**：`languages` 数组的行为是"跟随系统语言，匹配不到用第一个"。
   保留 English 会让英文 Windows 装出英文安装器。产品定位是中文，直接单语言最没有歧义；
   将来要做英文版，改回数组并打开 `displayLanguageSelector` 即可（一行配置）。
2. **不做自定义 NSIS 模板改完成页**：Tauri 的完成页文案写死在 `installer.nsi` 里，要改必须
   整份复制模板（几百行），Tauri 升级时会漂移。用 `installerHooks` 落一份 txt + 应用内引导，
   覆盖同样的信息量，维护成本低一个数量级。完成页保留默认的「运行 Mochi」勾选，装完直接进应用。
3. **引导放在聊天窗内做覆盖层，不做独立窗口/路由**：少一个 WebView 就少一套生命周期、
   IPC 与焦点问题；而且「去配置 Key」可以直接切到设置 Tab，形成闭环。
4. **首启自动弹窗而不是等用户发现**：「双击宠物打开聊天」没有任何视觉暗示，新用户大概率
   永远不知道。延迟 1.2s 是为了让麻薯先在角落出现，用户先建立"这是个会动的小东西"的印象。
5. **`onboardingDone` 放 settings 而不是 localStorage**：跟着应用数据走，重装/升级后仍然记得；
   且设置页回看引导 = 把它置回 false，零额外状态。
6. **刻意不提供"跳过且不再显示"**：新用户第一次关窗很可能只是切窗口，不该被判定为"看过了"。
   宁可多讲一次；如果后续觉得打扰，按施工单 P1-09 加一个"以后不再自动显示"的小字链接。

## 踩坑与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| hooks 文件中文乱码风险 | Tauri NSIS 模板是 `Unicode true`，脚本按 UTF-8 解析；无 BOM 时 NSIS 按 ANSI 处理中文 | 用 Node 给 `.nsh` 加 UTF-8 BOM（`ef bb bf`），并在文件头注释里写死这条约束 |
| 无法在沙箱里跑完整 `tauri build` 验证 | `vcvars64.bat` 内部调 `reg.exe` 被安全策略阻断 → `cl.exe` 环境不全 → `vswhom-sys`/`libsqlite3-sys` 编译失败 | 改用「`makensis` 单独编译 + 静默安装」做端到端验证：构造最小 `.nsi` 引入真实 hooks，编译通过；`/S` 安装后读取产物，确认 UTF-16LE 中文无乱码。完整打包留给用户在真实终端执行 |
| `MochiPlaceholder` 放在 `<h1>` 里会断行 | 该组件根节点是 `display:block` 的 `<svg>` | 标题去掉内联 SVG，头像改用 `assets/pet/idle.svg` 的 `<img>` |

### Rust 与能力配置逐行说明

`src-tauri/src/lib.rs` 只新增一个事件处理分支，没有迁移业务计时到 Rust：

1. `const EVT_HIDE_ALERT: &str = "ui://hide-alert";`：与 TS 协议常量同步。
2. `let handle = app.clone();`：为下一个 move 闭包单独持有廉价 AppHandle，避免所有权被前面的监听消耗。
3. `app.listen_any(EVT_HIDE_ALERT, move |_| {`：任何窗口/服务均可请求关闭提醒形象。
4. `if let Some(alert) = handle.get_webview_window("alert") {`：按 label 取得已有弹窗，窗口不存在则安全忽略。
5. `let _ = alert.hide();`：隐藏而不销毁 WebView；不自动确认计时，计时收尾仍归 TS 服务。
6. 两行结束花括号与 `);`：闭合可选窗口分支与监听注册。

`src-tauri/capabilities/default.json` 新增 `"sql:allow-execute"` 一行：授权现有 TS 建表与写入路径。官方 [default](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/sql/permissions/default.toml) 只含 load/select/close，[execute](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/sql/permissions/autogenerated/commands/execute.toml) 是独立能力（查询日期：2026-11-04）。

### Rust 修改逐语句说明

原生新增的业务仅为窗口交付队列与外部时钟唤醒；自然语言解析、业务倒计时、站立策略、提醒存储仍全部在 TS。新类型/方法/分支/每个关键语句的用途与取舍详见 [learning/09 原生逐语句走读](../learning/09-desktop-reliability.md)：

1. imports 增加 VecDeque/Mutex/Duration/Emitter；事件常量与 TS 同步。
2. AlertKind/AppAlert/AlertAck 负责可序列化载荷；AlertQueue 存 FIFO 与 needs_present，enqueue/acknowledge/dismiss 按 id 裁决。
3. Builder.manage 注册共享队列；invoke_handler 增加四个窄命令；setup 启动原生节拍。
4. alert CloseRequested 确认当前队头，pet/chat 仍隐藏；新 dragPet 监听请求 start_dragging。
5. position_and_show_alert 获取当前屏 work_area 和物理坐标；alert_position 用 i64 计算并夹紧，顶边改下方，最后 show 不夺焦。
6. present_alert 先广播正文再显示；失败保留 needs_present；show 首条失败回滚，get 读快照，ack 必须匹配当前 id，dismiss 只删指定 id。
7. 原生线程每秒 sleep，然后 run_on_main_thread 发 nativeTick 并重试 needs_present；四个同步命令同样在主线程执行，不将持 Mutex 的窗口操作改到后台。
8. 初始宠物位置改用 work_area 原点/尺寸，避免负坐标屏和任务栏遮挡；旧无 id hide/ack 仅在新队列为空时生效。
