# v0.9.2 — 素材导入页（双语 + 导入即改英文名）

## 目标

用户提出：「导入图片页面希望可以是双语的，告诉用户每个状态代表什么，只有导入项目当中
[的图片] 自动改为英文命名供项目使用。」

拆成三条需求，本版一次交付：

1. **有页面**：此前没有任何导入入口——自定义素材只能靠用户自己把文件放进 `pet-assets/`
   并手写英文状态名（`happy.png`）。放中文名文件（`开心.png`）永远不会生效，而用户不知道，
   只会觉得"放了图没反应"。
2. **双语 + 状态说明**：每个状态叫什么、**什么时候会出现**，中英并排。
3. **导入即改名**：导入的图片统一落成英文规范名（`happy.png` / `happy_2.png`）供项目使用，
   中文文件名被识别并翻译。

## 文件级实现细节

### Rust（`src-tauri/src/lib.rs`）

- 新增命令 `save_pet_asset(app, state, ext, base64) -> Result<String, String>`：
  - 状态白名单 `PET_ASSET_STATES`（10 个，与前端 `PET_STATES` 同集合）；
  - 扩展名白名单 `PET_ASSET_EXTS`（png/jpg/gif/webp/svg，`jpeg` 归一为 `jpg`）；
  - `PET_ASSET_MAX_BYTES = 16MB`，空文件直接拒绝；
  - 目录 `{appData}/pet-assets/` 不存在则创建；文件名由 `next_asset_file_name` 决定后写盘，
    **返回最终文件名**（前端预览只是预览，真实名字以写盘侧为准）。
- `next_asset_file_name`：`{state}.{ext}` → `_2` → … → `_9999`，极端情况用时间戳兜底（不覆盖）。
- `decode_base64`：手写解码（标准字母表 + `=` 填充，忽略空白）；脏输入返回 `Err` 不 panic；
  `data:` 前缀未剥离时给出可读错误。
- 命令注册进 `invoke_handler`，**不新增 capability**（自定义命令不经 ACL，权限面不变）。
- 单测 3 组：三种填充位、畸形输入、变体序号避让。

### 服务层（`src/services/pet-asset-import.ts`，新增）

- `STATE_DOCS`：十个状态的双语文案（页面与文档同源）。
- `guessStateFromFileName`：词干归一（去扩展名/序号/副本尾巴）→ 状态代码 → 别名精确 → 别名包含
  （按别名长度优先，避免「休息」抢「休息中」）。
- `extOfFileName`：扩展名归一 + 白名单，导入前就拦住 `.psd` 之类。
- `targetFileName`：与 Rust 同算法的预览名，额外接受 `reserved`（同批已排队的名字）。
- `readFileAsBase64`（`FileReader`）、`savePetAsset`（invoke）、`listUserAssets`、`fileNameOf`。

### 页面（`src/pages/chat/AssetsTab.tsx` + `assets.css`，新增）

- 结构：标题（中英）→ 说明（中文段 + 英文段）→ 选择图片 → 待确认列表 → 结果提示 → 状态说明列表 → 尺寸建议。
- 交互：选完不写盘；每行可改状态、可移除；「导入 N 张」才落盘。`file input` 的 `value` 每次清空，
  否则再次选同一个文件不触发 `change`。
- 状态卡片右侧显示"已有 N 张 / 内置图"，导入后立即刷新——用户能确认"我的图真的进去了"。
- 样式沿用项目浅粉体系（`#ff8fab` / `#f0e4e8` / `#a39690`），整页自身滚动。

### Tab 接线（`src/pages/chat/ChatApp.tsx`）

无（不引入 `tauri-plugin-fs` 与 base64 crate，见下节取舍）。

## 设计取舍

**① 为什么用 base64 走命令，而不是加文件系统插件**
导入是低频操作，图片通常 < 2MB。为它引入 `tauri-plugin-fs` 要加 npm + Cargo 两处依赖、
一组 ACL 权限（`fs:allow-write-file` + scope），权限面比"一次 base64 传输"贵得多。
反过来，如果只加 base64 crate 也要多一个依赖；解码算法 20 行、有单测，自己写更划算。

**② 为什么校验放 Rust**
前端拿不到文件系统权限，写入能力只在 Rust。若"前端过滤一次、Rust 再信一次"，等于没过滤：
白名单、大小、空文件都必须和 `fs::write` 在同一侧，否则一个被注入的前端就能往应用数据目录
写任何东西。

**③ 为什么先确认再落盘**
改名是**不可逆的用户素材操作**：把一张图错放进 `sad` 比多点一次"导入"更让人恼火。
确认列表还顺手完成教学——用户直接看到"开心.png → happy.png"，下次就知道约定是什么。

**④ 为什么改名发生在导入这一步（而不是运行时兼容中文名）**
运行时解析（`parseAssetName` / Rust `_of_file_name`）只认状态代码，是回退链与变体池的基准；
为中文名加一层映射会让"同一状态两种名字"长期共存，序号/轮换/去重都要跟着复杂。
导入时一次性落成规范名，运行时保持"一个状态一个英文名"的简单契约。

**⑤ 为什么做成第 5 个 Tab 而不是设置里的分区**
设置页是 480px 窄栏、已经有 8 个分区；素材说明有 10 条状态 + 待确认列表，塞进去会把设置页
压成滚动条地狱。Tab 是本项目既有的"页面"单位，keep-alive 也不额外付挂载成本。

## 踩坑与解决

### ① 常量长度写错

`PET_ASSET_EXTS: [&str; 6]` 实际只有 5 个元素，编译期直接报 E0308。教训：白名单这类
"个数会变"的常量，长度靠编译器提醒比靠眼睛数靠谱（也可以写成 `&[&str]` 切片）。

### ② Tauri 命令参数命名的坑位预判

Tauri v2 默认把 Rust 的 `snake_case` 参数按 `camelCase` 从 JS 取值。为避免"名字对不对"
这种不由编译期发现的问题，参数直接取名 `base64`（单词），JS 侧同名传参，不依赖转换规则。

### ③ 验证手段：CDP 驱动文件选择

`<input type="file">` 没法用 `element.click()` + 脚本赋值（安全限制）。用 WebView2 远程
调试口（`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9226`）连上 chat 页，
`DOM.setFileInputFiles` 把三个中文名测试文件塞进 input，再 `click()` 导入按钮，全程脚本化，
不需要人工点。这套法子也顺带验证了「按中文名识别状态」「同批序号递增」。

### ④ 测试素材必须回收

验证用的是 1×1 透明 PNG（文件名 `开心.png` 等）。验证完立刻删掉 `pet-assets/`（该目录在
验证前不存在）——否则用户触发 happy 时会看到一个 1 像素的点，比没有图更困惑。
