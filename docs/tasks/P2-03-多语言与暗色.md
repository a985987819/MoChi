# P2-03 多语言与暗色主题

- **状态**：open
- **优先级**：P2（真实用户基本是中文单语言用户，但代码里的硬编码会越来越难改）
- **依赖**：无（但两步都建议先做"抽取"再做"功能"）

## 背景

- 全站中文硬编码（`docs/pet-assets.md` 的素材导入页是唯一双语特例）。
- 颜色以字面量散落在多个 CSS 里（`#ff8fab`、`#f0e4e8`、`#a39690`…）。
  v0.9.0 的 P2-01（暗色模式）就是因此被明确推迟的。

## 目标（分成两个独立任务，可分别认领）

**A · 主题变量化 → 暗色主题**

1. 把所有颜色抽成 CSS 变量（`--surface` / `--text` / `--text-muted` / `--border` / `--accent`…），
   在 `:root` 定义浅色，在 `@media (prefers-color-scheme: dark)` 或 `[data-theme]` 定义深色；
2. 宠物窗是**透明背景**，暗色只影响聊天窗/提醒窗/设置面板，别给宠物窗加底色；
3. 素材图片不要做任何滤镜（用户素材在暗色下也照原样显示）。

**B · i18n**

1. 建立 `src/shared/i18n/`：`zh-CN.ts`（唯一事实源）+ `en.ts`（类型约束 key 一致）；
2. `useT()` hook + 设置里的语言项（默认跟随系统，可强制）；
3. 分批迁移：先聊天窗与设置（用户停留最久），再提醒窗与右键菜单；
4. **不要迁移动态文案生成器**（`pet-chatter-lines.ts` 的 144 条随机文案）：那需要真正的文案创作，
   机械翻译只会更差，先把它们留在中文。

## 实施结论

- 顺序偏离任务单建议（未先迁聊天窗/设置页全文）：聊天窗正文混着 LLM 中文回复，半翻会出现混合语言界面；首批选择**完整单元**（Tab 栏/提醒中心/待办/番茄钟/弹窗/菜单），聊天窗与设置页其余分区在扫描脚本 PENDING 建档为下一批。理由见 v0.19.0 文档取舍 §3-4。
- 扫描脚本 `pnpm lint:i18n`：615 处存量建档、新增未建档即失败。

## 验收标准（原文）

- [ ] A：浅色/深色都能通过对比度检查（正文 ≥ 4.5:1）；宠物窗在两种主题下视觉一致。
- [ ] B：`en.ts` 与 `zh-CN.ts` 的 key 类型级一致（`satisfies Record<MessageKey, string>`，缺 key 编译报错）；
      切换语言不需要重启；有一个"扫描硬编码中文"的检查脚本或清单。
- [ ] 两个子任务各自有版本文档；不要混在一个 commit 里。

## 坑

- CSS 变量改造是**大范围机械改动**，容易与同时在改 UI 的 agent 冲突——
  认领这个任务要在 `TASKS.md` 登记"占用：全站 CSS/组件"，并告知其他人避开。
- 暗色不要简单反色：项目现在是"奶油粉"体系，深色需要一个对应的暖灰底，不然会变冷硬。
- i18n 的插值与复数：中文没有复数，英文有；`{count} items` 这类要留出 plural 处理位置
  （先用简单函数，不急着引 i18next）。
