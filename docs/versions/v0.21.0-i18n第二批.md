## 设计取舍

1. **AssetsTab 保持双语页面形态**：它的双语标签（中/英对照）本身就是教学内容
   （v0.9.2 的设计目标），只迁移动态字符串（通知/计数）——locale=en 时提示语变英文，
   教学对照保留。
2. **组件内 t 引用的稳定性**：t() 运行时读模块级 locale，useCallback 旧引用不会
   翻译过期——依赖数组漏 t 无正确性风险（对比 v0.15 的配置渗漏教训）。
3. **MarkdownView（非 hook 组件）直接调 t()**：t 不依赖 hook 上下文，memo 组件
   里也能用——这是 core.ts 与 react.ts 分文件的原因之一。
4. **字典值内的引号**：英文值里的引号统一用弯引号（“”），避免与 JS 双引号转义
   相互干扰（本轮踩了三次的坑）。
5. **panicNote 的路径反斜杠**：字典值里 `logs\last-panic.txt` 必须写 `\\`（JS 转义），
   换行用字面 `\n`——脚本批量注入时 Write 工具会把 `\n` 写成真换行，需要二次修正。

## 踩坑与解决

- 字典批量插入脚本三次踩 shell/Write 转义坑（`\n` 成真换行、`\"` 成裸引号、
  字典收尾符重复）——最终以「脚本注入 + tsc 立即校验 + 定点 Edit 修复」节奏收敛。
  教训：**机械改字典后每次都跑 tsc**，别攒批。
- SettingsTab 迁移脚本 2 处缩进不匹配（NOT FOUND）——精确匹配脚本对缩进敏感，
  失败即 exit 1 的设计救了正确性（不会半迁移）。
