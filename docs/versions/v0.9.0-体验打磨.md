## 设计取舍（Night 3）

1. **流式走 Markdown 主案**：80ms 节流后 ~12fps 重解析成本可控，不走纯文本降级案；
   光标改 CSS ::after 挂最后元素（行内 span 会被 Markdown 块级结构挤出去）。
2. **全等断言以工具源码为事实源**：facade 拉起 tauri 依赖链进不了 node 测试，
   fs 扫描 `name: "..."` 同样机械且以代码为准（复制名单反而会漂移）。
3. **错误三层结构**：人话 headline / 可执行 action / 折叠 details——每层有受众；
   aborted（用户主动停止）是中性提示不是报错。
4. **复制取 DOM innerText**：渲染文本语义 = 用户所见，自己写 markdown→text 反向
   解析不如信浏览器。
5. **重试挂具体条目**：failed/retryText 存在 assistant entry 上，多轮失败各自
   重发自己的输入；错误条重试（最近一次）与气泡重试（该轮）共用 doSend。
6. **chips 不自动发送**：保留控制权（施工单附录 B），填入后聚焦输入框。

## 设计取舍（Night 4）

1. **快捷键键位 v1 写死**：自定义键位 = 键盘捕获 UI + 冲突矩阵，收益低；
   开关先行。注册在 Rust（OS 级钩子必须原生），占用静默降级 + 回执事件提示。
2. **幂等 unregister→register**：开关反复切换/启动重复应用都安全。
3. **自启默认关**（红线级约定）：设置是事实源，系统项是投影——被系统清理后
   下次启动自动恢复声明；失败不弹窗（重试也不会成功，eprintln 留痕）。
4. **宠物缩放三步纪律**：改尺寸（逻辑像素，DPI 归 Tauri）→ 锚点重定位
   （右下角——桌宠待在角落，中心缩放会让它跳走）→ clamp 自愈（复用 P0-04）。
   窗口归 Rust、形象归 CSS 变量，同听一条事件各改各层。
5. **「稍后」≠「重置」**：ack = stretch 奖励 + 整轮重置；snooze = deadline 推 5 分钟
   无奖励动画。UI 复用一张卡片，语义必须分流（stopPropagation 防整卡点击兜底）。
6. **CI 分层**：门禁（每次 push，ubuntu 快）与发布（tag，双平台重）两条管道；
   cargo check 单独 windows job（目标平台依赖只在 windows 真正编译）。

## 设计取舍（Night 2）

1. **气泡独立窗口**（不复用 alert）：alert 是模态确认语义（ack/超时状态机），
   气泡是非模态语义，混用互相污染生命周期。
2. **chatVisible 不做跨窗口状态**：document.visibilityState 在 WebView 隐藏时变
   hidden，聊天窗自查即可——比施工单建议的方案少一条事件协议。

4. **托盘菜单纯静态**：开始/停止并存（Service 层幂等）而非动态重建菜单；
   tooltip 去重缓存避免每秒系统调用。
5. **反向事件沿用 state:// 命名空间**：托盘（Rust）→ 宠物窗 Service 与
   chat 窗 → 宠物窗 Service 同构，不发明第三种协议。
6. **菜单夹紧实测尺寸**：估算常量必然漂移（施工单点名坑），getBoundingClientRect

## 设计取舍（Night 1）

1. **P0-02 防抖独立成文件**：settings.ts 顶层 import plugin-store，直接在里面写防抖
   就无法在 node 环境单测（vite.config.ts 测试纪律）。机制纯函数化 + settings.ts 5 行适配，
   比引入 vi.mock 更符合项目分层。
2. **P0-02 离散控件不防抖**：下拉/开关是单次事件，直存 + 广播；防抖只给字符级输入。
   blur/卸载时 flush 补齐防抖的「延迟落盘」代价。
3. **P0-03 授权集中在启动**：授权框是「预期内的打断」，放启动时；到点时刻只查权限。
   插件只暴露 granted 布尔值（没有 denied/not-asked 之分），未授权时同时给
   页面内请求 + 系统设置路径两条恢复路。
4. **P0-04 选 window-state 插件**：源码核实其内部跟踪 Moved + RunEvent::Exit 自动落盘
   （2.5.0 第 528-530 行），自己写保存逻辑等于重造；只开 POSITION——VISIBLE 会破坏
   chat「隐藏启动」设计。恢复后自做可见性校验（插件不校验多屏悬空）。
5. **P0-04 工作区查询下沉平台 API**：Tauri 2 的 Monitor 无「工作区」概念（只有
   size/position/scale_factor），避开任务栏必须 SPI_GETWORKAREA；用 windows crate
   （0.62 已在依赖树，不新增编译单元）+ `#[cfg(windows)]` 隔离，macOS 保持整屏算法。

## 手感与交互优化（2026-11-06）

用户需求：「拖动、点击不掉帧，动画曲线舒适」。做法：先用证据定位真实的延迟/掉帧源，
再逐项修，不做无验证的"感觉系"调参。

### 文件级改动

| 改动 | 文件 | 解决什么 |
|---|---|---|
| **点击即时反馈**：PetGestureActions 新增可选 `clickFeedback()`，抬指瞬间触发 | gestures.ts +3 例测试 | 原实现里弹跳在 singleClick 内，要等 500ms 双击判定窗口结束才播——点击到反馈有半秒死区，是最大的"不跟手"源。现在视觉反馈 0ms，语义动作（重置计时/暖心气泡）仍按判定结果分发 |
| **窗口唤回轻过渡**：`playShowTransition`（WAAPI 淡入+上浮 160ms）+ `onWindowShown`（visibilitychange） | shared/show-transition.ts（新）、PetApp/ChatApp | `window.show()` 是硬切闪现；动画走合成器（opacity/transform），**不重挂子树**（聊天窗全量 DOM 重建正是掉帧源） |
| **alert 弹窗每次重播入场动画**：`key={alert.id}` 重挂卡片 | AlertApp.tsx | 窗口隐藏不销毁，CSS 入场动画只在首次挂载播过——第二条提醒起是"硬蹦出来"；卡片节点极小，按 id 重挂零成本 |
| **右键菜单展开动画**：140ms ease-out 上浮淡入 + reduced-motion 关闭 | context-menu.css | 菜单原是瞬时出现；140ms 是"确认出现"而不挡操作的窗口 |
| **合成层提示**：`.pet-stage__pet`/`.pet-bubble` 加 `will-change` | pet.css | 待机漂浮是无限动画——常驻独立合成层，避免 float/bounce 切换时层提升抖动；透明窗口逐帧合成不占主线程布局 |
| **拖动可供性**：宠物窗 `cursor: grab` | pet.css | 拖动手势无任何视觉暗示；光标是最便宜的提示（P1-10 只能文字备忘），拖动中由 OS 接管光标 |

### 明确不做的（防过度工程）

- **拖动"握持"视觉（暂停漂浮）**：start_dragging 交给 OS 后，前端拿不到可靠的
  drag-end 信号（pointerup 不回投给 WebView）；要跟踪 WindowEvent::Moved 需要
  新事件协议，收益/风险比不划算，留待后续版本。
- **keyframes 曲线重调**：现有 mochi-bounce/bubble-pop 已是 cubic-bezier ease-out
  家族，与新增动画统一为 (0.22,1,0.36,1)（easeOutQuint 近似）——不引入弹簧库。
- **性能目标与验证边界**：transform/opacity-only 动画在合成器线程跑，"不掉帧"
  由浏览器合成管线保证；主线程侧的掉帧源（1Hz 重渲染）经核查不存在

## 交互第二批次：拖拽握持、加载收口与 Tab keep-alive（2026-11-08）

用户需求：拖拽过程不掉帧、各阶段动画、异常明确告知、必要的 loading。

### 拖拽链路（"被拿在手里"的物理感）

- **Rust 边界检测**（lib.rs）：`on_window_event` 捕获宠物窗 `WindowEvent::Moved`——
  首次移动广播 `state://pet-drag-changed {dragging:true}`；结束由既有原生节拍判定
  （上次移动静默 400ms → 广播 false）。**边界各广播一次**，移动中零 IPC（60Hz 的
  Moved 不可能逐个转发，那是前端被自己拖慢的根源）。状态机抽纯函数
  `drag_transition`（+2 例 Rust 单测：首动开始/拖中不重复/静默窗判定/唤醒补判）。
- **前端握持动画**（PetApp + pet.css）：握持 = 漂浮暂停（animation-play-state）+
  `scale: 1.04` 微放大；放下 = 类名移除，160ms ease-out 回落即"落地"。
  `scale` 用独立 CSS 属性与 transform 动画叠加，互不打架。
- **为什么不掉帧**：窗口位移由 OS 合成器完成（start_dragging 原生拖动循环），
  WebView 零重绘参与；拖拽期间唯一的前端成本是"暂停一个合成层动画"。
- 已知小行为：程序性 set_position（如宠物缩放 P1-15）也会触发 Moved → 短暂握持

### LocalQA 路由（src/rag/local-qa.ts）

- **两条边界**：大模型未连接时，域内问题（康复/营养/膳食/运动/热量）本地检索直接
  作答（离线/零成本/毫秒级）；范围外问题输出引导话术（含知识库规模与连接三步）。
  大模型已连接时不走本地路由——带工具的模型对话质量更高，本地路由是无 LLM 的兜底。
- **置信判定不用 BM25 分数阈值**（分数是语料库相对值不可跨库比较），改用可解释的
  **查询实义词元覆盖率 ≥0.45 + top1 分数下限 1.0**。
- 调参复盘（评测 6/10 → 10/10）：①bigram 窗口跨词碎片（炎怎/么锻/要补）虚增分母
  → 覆盖率计算侧剔除含虚词字符的 bigram（不动全局 tokenizer）；②"什"字漏出虚词表
  （风什/吃什）→ 补 什/啥/样；③"锻炼↔练习"同义缺口 → 组扩展；④补钙条目补
  缺钙/抽筋关键词。**域外 6 题误答率 0**（路由的另一半同样被考卷锁住）。
- ChatTab 接线：`!isProviderReady` 时先过 LocalQA——answered 直接渲染（📚 徽标 +
  逐条来源 + 面诊提示尾注，**不落库**：查证型对话不进情景记忆，持久化仍是 Facade
  单一所有者）；out-of-scope 输出引导气泡（非红色报错——能力边界教育不是故障）。
  Provider 就绪时完全走原 LLM 路径，行为不变。
- search_health_advice 工具描述扩展康复/营养域（LLM 模式下模型也能检索到新语料）。
