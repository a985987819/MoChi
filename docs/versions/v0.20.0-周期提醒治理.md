# v0.20.0 — 周期提醒治理：跳过某一次 + 取消整串

> P1-01 任务文件「遗留」清单的两项，本次递归清账完成。2026-11-18。

## 目标

任务单原文："周期提醒的'跳过某一次'（比如周末不想被吵）需要更复杂的规则（RRULE 子集）；
取消整串需要按 series_id 批量操作"。两项都做了**最小正确实现**，不引入 RRULE。

## 功能清单

- **跳过某一次**（`skip_reminder` 工具 + 提醒中心按钮）：行保持 active 置 `skip=1`，
  调度器触发时**静默交付**（写 acknowledged_at 作为跳过凭证、不弹窗不进聊天不放音效
  不变宠物状态），并照常 scheduleNext——周期不断串，这正是跳过与取消的语义分界。
- **取消整串**（`cancel_reminder(all=true)` + 提醒中心按钮）：按 series_id 逐行条件
  取消全部 active 行；部分行恰好被调度器认领时如实返回已取消子集。
- `list_reminders` 输出补 `repeat` / `series` / `skip_next`——模型据此判断该跳过还是取消。
- 提醒中心进行中列表：周期行新增「跳过一次 / 取消整串」按钮 + 「下次将跳过」标记
  （i18n 双语）。

## 设计取舍

1. **skip 是列不是独立行**：RRULE 子集（EXDATE）在这里过度设计——周期行的"下一次"
   是触发时才插入的，给当前 active 行打标即可表达"下一次别响"；标记随行触发而消费，
   新行天然 skip=0（INSERT 不含该列）。
2. **静默交付必须写 acknowledged_at**：不写的话，重启恢复逻辑会把 fired+未确认的行
   重新弹出来——"跳过"就变成了"延迟弹一次"，正好违背用户意图。
3. **跳过不进聊天历史**：用户要的是"别吵"，历史里出现一条没弹过的记录反而是噪音；
   提醒中心历史里该行以「已跳过」徽标呈现（skip 字段驱动 StatusChip 分支）。
4. **工具错误信息面向模型自愈**：skip 对一次性提醒返回解释性错误（跳过=取消，请用
   cancel），cancel(all) 对一次性提醒同理——01 §4.3 的自愈闭环靠可执行的纠错话术。
