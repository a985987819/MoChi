## 文件级实现细节

### 内核（src/agent/）

- `tools/validate-schema.ts`：错误文案面向模型可读（回传后模型能自我纠正）。
- `tools/registry.ts`：`AppServices`（todos/pet）经 `ToolContext` 注入——内核不 import 业务；`risk` 分级字段（read/write/destructive，07 §4.3）。
- `core/agent.ts`：`runAgent` 异步生成器；终止条件 `calls.length===0`；assistant 消息带 `toolCalls` 压回历史后紧跟 tool 结果（协议顺序不可乱）；transport 错误抛出、工具错误回填的双轨错误处理。
- `core/prompt.ts` + `core/context-builder.ts`：`buildInitialMessages` 预留 memories/retrievedKnowledge 入参（v0.5/v0.6 接口已立，本版不用改）。
- `facade.ts`：`runTurn` 每回合开始 setMood('thinking',60s)、每个 text-delta 续期 talking 12s、step-end 续期 thinking；停止输出后自然回落 idle。

### 工具（src/agent/tools/）

- `todo.ts`：4 工具均为 TodoService 薄封装；`delete_todo` risk=destructive、返回被删条目（07 可追溯）；错误文案引导模型先 list_todos 再操作。
- `pet-state.ts`：枚举只含 happy/sad（08 §2 精化 01 §4.5：thinking/talking 应用驱动、系统状态归计时器）；经 `state://set-mood` 跨窗口遥控宠物窗 PetStateManager。

### 服务与 UI

- `services/todos.ts`：store(todos.json) 持久化 + subscribe/snapshot；`remove` 返回被删条目。
- `TodosTab.tsx`：订阅刷新 + 手动添加输入框（UI 通道）+ 完成勾选/删除。
- `ChatTab.tsx`：发送走 `agentFacade.runTurn`；`note` 条目展示工具轨迹（协议历史过滤掉 note）。

### 依赖变化

- npm/cargo：零新增。

## 设计取舍

1. **协议历史在 v0.4.0 只存 UI 文本轮次**（tool_calls 明细跨轮丢弃）：协议合法（新回合从纯文本重开）、上下文小；v0.5.0 换 SQLite 全协议历史——runAgent 内已留同步点注释。
2. **set_pet_state 枚举收窄为 happy/sad**：能力面最小化（07）；thinking/talking 应用驱动避免"模型自导自演"。
3. **note 轨迹条目不进协议**：用户可感知工具活动，但不污染模型上下文。
4. **待办 UI 通道必须有**（手动添加框）：07 双入口铁律——Agent 通道坏了 UI 仍可用。
5. **due 传用户原话不解析**：防幻觉具体时刻；时间语义归 v0.7.0 create_reminder。
