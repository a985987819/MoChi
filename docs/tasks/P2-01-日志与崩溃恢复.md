# P2-01 结构化日志与崩溃恢复

- **状态**：done（v0.16.0，2026-11-17；真机跨天/panic 验证待用户）
- **优先级**：P2（不影响日常使用，但每次排障都在还债）
- **依赖**：无
- **涉及文件**：`src-tauri/src/lib.rs`（panic 钩子已存在）、新增 Rust 日志模块、
  `src/services/log.ts`（前端上报）

## 背景

- release 是 `windows_subsystem = "windows"`：**没有控制台，所有 `eprintln!` 直接丢失**。
  v0.9.1 排查"开机自启不生效"时，只能临时加埋点、构建带控制台的调试版才拿到证据。
- 目前唯一落盘的是 panic 钩子（写到系统临时目录，用户找不到，也不轮转）。
- 前端异常（IPC 失败、素材加载失败）完全没有记录。

## 目标

- 统一日志文件：`{appData}/logs/mochi-YYYY-MM-DD.log`，按天切分，保留 7 天；
- 级别：`error` / `warn` / `info`（不引入 trace，桌面应用不需要）；
- Rust 与前端写同一个文件（前端经一条命令上报，避免第二套写入逻辑）；
- **脱敏**：绝不写 API Key、聊天正文、提醒正文；只写"发生了什么 + 长度/计数"；
- 崩溃：panic 钩子改为写同一目录，并在下次启动时把上次的 panic 摘要显示在"关于"里。

## 实施记录

- 见 docs/versions/v0.16.0-日志与崩溃恢复.md（采纳全部设计建议；chrono 因已是传递依赖而引入，任务单禁的是 tracing）

## 设计建议（原文）

- Rust 侧不要引 `tracing`（体积 + 配置成本）；一个 `Mutex<File>` + `log_path()` + 简易轮转足够，
  与本项目"极简本地时间戳"的既有风格一致（见 `chrono_like_now`）。
- 前端：`src/services/log.ts` 暴露 `logError(scope, error)`，内部 `invoke("append_log", {...})`；
  **失败静默**（日志不能反过来制造错误）。
- 轮转：启动时清理 7 天前的文件；单文件超过 5MB 直接换名（`-1`）并开新文件。
- 脱敏：提供一个纯函数 `redact(message: string): string`，按已知前缀（`sk-`）与超长正文截断，
  **单测覆盖**（这是唯一能自动验证的部分）。

## 验收标准

- [ ] `redact` 单测：Key 形态被打码、超长文本被截断、正常文本不变。
- [ ] 启动后生成当天日志文件；连续两天（可改系统时间或用注入时钟）能切分。
- [ ] panic 后日志里有记录，重启应用能在"关于"看到上次崩溃摘要。
- [ ] `grep` 日志不出现任何 `sk-` 明文（手工检查一次）。

## 坑

- 别把日志写到临时目录（用户/支持者拿不到）；`appData` 才对。
- 日志写入必须在**主线程之外**或加锁串行，别在 native tick 里做同步 IO。
- 不要记录窗口标题/进程名（隐私红线，`docs/learning/08` §3）。
