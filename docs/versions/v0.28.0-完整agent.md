# v0.28.0 — 完整 agent：自主执行 + 桌面操作工具

> 用户诉求："希望它成为一个完整的 agent，自行配置 api key 之后，会自动调用工具链，
> 完成常规的操作"。2026-11-19。

## 现状核查

工具链与协议层已完整：15 个工具、标准 OpenAI 兼容 tool_calls 流式解析（DeepSeek
官方格式一致）、自主多步循环（MAX_STEPS=8）、单会话协议持久化 + 上下文预算。真正
的缺口有两个：

1. **常规操作面窄**：没有"打开网页/打开数据目录"这类桌面操作工具——agent 说得了
   做不了；
2. **提示词偏保守**：【工具使用】写的是"用户表达了意图时才调用"——模型会倾向反问
   而不是直接执行。

## 功能清单

1. **新工具 ×2**：
   - `open_url(url)`：系统浏览器打开网页——只接受 http/https（scheme 白名单
     `validateHttpUrl` 纯函数 + opener 插件层第二道校验，file:/javascript: 拒绝）；
   - `open_data_folder()`：定位应用数据目录（聊天/设置/素材所在处，备份入口）。
2. **提示词【自主执行】段**（prompt.ts）："用户请求可由工具完成时**直接调用工具
   执行**，完成后一句话汇报；不反问'要不要我帮你做'，不只给步骤让用户自己动手；
   多步任务按顺序多次调用，中间结果自行衔接"。
3. 工具轨迹文案：tool.openUrl / tool.openDataFolder（双语）。
4. facade 注册 + tool-labels 补齐（全等单测自动校验新工具）。

## 设计取舍

1. **零新增权限**：opener 插件已在 capability（设置页外链/数据目录入口都在用）——
   agent 工具是同一能力的薄封装（learning/07 §6.3：意图层归 Agent，执行层走
   应用已有 Service）。
2. **scheme 白名单双保险**：工具层 validateHttpUrl（单测钉死 file:/javascript:
   拒绝）+ opener 插件层 scheme 校验。打开网页是外部动作（risk: write），
   UI 轨迹可见可追溯。
3. **自主执行写进提示词而非改循环**：MAX_STEPS=8 的循环机制本身已是自主的——
   模型"不敢调工具"是提示词引导问题，不是架构问题。
4. **任意路径浏览刻意不做**：文件管理器的事不是桌宠的事（learning/08 边界——
   "能看用户文件"是隐私红线，数据目录是唯一白名单入口）。
