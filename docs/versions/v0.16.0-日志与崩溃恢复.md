# v0.16.0 — 结构化日志与崩溃恢复（P2-01）

> 任务单：`docs/tasks/P2-01-日志与崩溃恢复.md`。完成于 2026-11-17。

## 目标

release 版不再"排障全靠猜"：

1. 统一日志文件 `{appData}/logs/mochi-YYYY-MM-DD.log`，按天切分、保留 7 天、单文件超 5MB 换名；
2. Rust 与前端写同一个文件（前端经 `append_log` 命令上报）；
3. 脱敏铁律：绝不写 API Key / 聊天正文 / 提醒正文 / 窗口标题——只写"发生了什么 + 长度/计数"；
4. panic 钩子写进同一目录；重启后「关于」页显示上次崩溃摘要。

## 功能清单

- Rust 日志模块：`append_log_line_at`（含轮转）/ `redact_message` / `cleanup_old_logs`；
- 新命令 `append_log`（async，tokio 线程池执行——同步 IO 不占主线程）与 `get_last_panic`；
- panic 钩子改写 `last-panic.txt`（单文件覆盖，供「关于」页展示）+ 当天日志留痕；
- 前端 `src/services/log.ts`：`logError/logWarn/logInfo`（fire-and-forget，失败静默）、
  `redact`、`installGlobalErrorLogging`（window error + unhandledrejection 兜底）；
- 接线站点：db 连接失败、提醒扫描失败、合并交付失败、通知发送/权限/点击路由失败、
  设置保存失败、两窗口全局异常兜底；Rust 侧：自启失败、快捷键被占用、托盘图标缺失、
  单实例唤起失败（eprintln 保留供 dev 模式）；
- 「关于」页：崩溃摘要展示（无记录不显示）+ 日志位置说明；
- 版本号对齐：package.json / tauri.conf.json / Cargo.toml → 0.16.0
  （v0.14/v0.15 收口时漏了 bump，本版一并补齐）。

## 新增依赖

- `chrono`（`default-features = false, features = ["clock"]`）：本地日期/时间戳。
  **它本来就是 Cargo.lock 里的传递依赖**，声明为直接依赖零新增编译成本；
  手写民用历换算（UTC→本地日期）是新的出错面，不如用久经考验的实现。
  任务单禁的是 tracing（体积+配置成本），不是 chrono。

## 设计取舍

1. **逐条 open-append-close，不持有长寿命句柄**：量级极低（error/warn/info 事件），
   换来跨天/轮转的简单正确——长句柄在轮转后会继续写旧文件（append 语义），逐条
   开合没有这个问题。async 命令里的同步 IO 阻塞 tokio worker 几毫秒，可接受。
2. **panic 钩子拿不到运行时配置**：它在 Builder 之前运行，appData 按平台规则手动
   推导（Windows = `%APPDATA%\com.mochi.pet`、macOS = `~/Library/Application
   Support/com.mochi.pet`），identifier 常量与 tauri.conf.json 同步（注释互指）；
   推导失败退回临时目录（旧行为）——有迹可循总比没有强。
3. **脱敏不用 regex crate**：就两个前缀模式，手写扫描 + 词边界校验足够（前端用
   JS 内建正则同规则，双端各一道防线）。
4. **`last-panic.txt` 不主动清除**：它是"上一次崩溃"的凭证，「关于」页每次都能
   看到上次崩溃时间，直到下一次崩溃覆盖。redact 已把单条消息截到 800 字符，
   文件不会膨胀。
5. **扫描失败每秒记一条是刻意保留的节流上限**：提醒扫描是秒级重试，连续失败会
   每天 86400 条——真实场景里这是磁盘故障级别的事件，宁可吵。常规站点（通知、
   设置保存）都是一次性动作，无此顾虑。

## 踩坑与解决

- **"task-skill" 被误伤**：手写掩码最初只查后缀 token，`task-skill-1` 里的
  `sk-` 命中并打码成 `task-***`。修复：前缀必须出现在**词边界**（前一个字符
  不是 `[A-Za-z0-9_-]`）；前后各一条测试钉死。
- **Windows mtime 测试**：构造"旧文件"用 std `File::set_modified`（Rust 1.75+ 稳定、
  跨平台）——最初想用 windows crate 的 SetFileTime，既麻烦还要给 Cargo.toml 加
  测试专用 feature，标准库 API 已经够了。
- **vitest node 环境没有 window**：`installGlobalErrorLogging` 加环境 guard，
  测试用 `vi.stubGlobal` 装记录型 window。
