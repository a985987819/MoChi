## 设计取舍（Night 3）

1. **流式走 Markdown 主案**：80ms 节流后 ~12fps 重解析成本可控，不走纯文本降级案；
   光标改 CSS ::after 挂最后元素（行内 span 会被 Markdown 块级结构挤出去）。
2. **全等断言以工具源码为事实源**：facade 拉起 tauri 依赖链进不了 node 测试，
   fs 扫描 `name: "..."` 同样机械且以代码为准（复制名单反而会漂移）。
3. **错误三层结构**：人话 headline / 可执行 action / 折叠 details——每层有受众；
   aborted（用户主动停止）是中性提示不是报错。
4. **复制取 DOM innerText**：渲染文本语义 = 用户所见，自己写 markdown→text 反向
   解析不如信浏览器。
5. **重试挂具体条目**：failed/retryText 存在 assistant entry 上，多轮失败各自
   重发自己的输入；错误条重试（最近一次）与气泡重试（该轮）共用 doSend。
6. **chips 不自动发送**：保留控制权（施工单附录 B），填入后聚焦输入框。

## 设计取舍（Night 4）

1. **快捷键键位 v1 写死**：自定义键位 = 键盘捕获 UI + 冲突矩阵，收益低；
   开关先行。注册在 Rust（OS 级钩子必须原生），占用静默降级 + 回执事件提示。
2. **幂等 unregister→register**：开关反复切换/启动重复应用都安全。
3. **自启默认关**（红线级约定）：设置是事实源，系统项是投影——被系统清理后
   下次启动自动恢复声明；失败不弹窗（重试也不会成功，eprintln 留痕）。
4. **宠物缩放三步纪律**：改尺寸（逻辑像素，DPI 归 Tauri）→ 锚点重定位
   （右下角——桌宠待在角落，中心缩放会让它跳走）→ clamp 自愈（复用 P0-04）。
   窗口归 Rust、形象归 CSS 变量，同听一条事件各改各层。
5. **「稍后」≠「重置」**：ack = stretch 奖励 + 整轮重置；snooze = deadline 推 5 分钟
   无奖励动画。UI 复用一张卡片，语义必须分流（stopPropagation 防整卡点击兜底）。
6. **CI 分层**：门禁（每次 push，ubuntu 快）与发布（tag，双平台重）两条管道；
   cargo check 单独 windows job（目标平台依赖只在 windows 真正编译）。

## 设计取舍（Night 2）

1. **气泡独立窗口**（不复用 alert）：alert 是模态确认语义（ack/超时状态机），
   气泡是非模态语义，混用互相污染生命周期。
2. **chatVisible 不做跨窗口状态**：document.visibilityState 在 WebView 隐藏时变
   hidden，聊天窗自查即可——比施工单建议的方案少一条事件协议。
3. **Rust 纯路由不存业务文本**：气泡载荷原样转发，窗口隐藏后零残留。
4. **托盘菜单纯静态**：开始/停止并存（Service 层幂等）而非动态重建菜单；
   tooltip 去重缓存避免每秒系统调用。
5. **反向事件沿用 state:// 命名空间**：托盘（Rust）→ 宠物窗 Service 与
   chat 窗 → 宠物窗 Service 同构，不发明第三种协议。
6. **菜单夹紧实测尺寸**：估算常量必然漂移（施工单点名坑），getBoundingClientRect
   + useLayoutEffect 在 paint 前修正。

## 设计取舍（Night 1）

1. **P0-02 防抖独立成文件**：settings.ts 顶层 import plugin-store，直接在里面写防抖
   就无法在 node 环境单测（vite.config.ts 测试纪律）。机制纯函数化 + settings.ts 5 行适配，
   比引入 vi.mock 更符合项目分层。
2. **P0-02 离散控件不防抖**：下拉/开关是单次事件，直存 + 广播；防抖只给字符级输入。
   blur/卸载时 flush 补齐防抖的「延迟落盘」代价。
3. **P0-03 授权集中在启动**：授权框是「预期内的打断」，放启动时；到点时刻只查权限。
   插件只暴露 granted 布尔值（没有 denied/not-asked 之分），未授权时同时给
   页面内请求 + 系统设置路径两条恢复路。
4. **P0-04 选 window-state 插件**：源码核实其内部跟踪 Moved + RunEvent::Exit 自动落盘
   （2.5.0 第 528-530 行），自己写保存逻辑等于重造；只开 POSITION——VISIBLE 会破坏
   chat「隐藏启动」设计。恢复后自做可见性校验（插件不校验多屏悬空）。
5. **P0-04 工作区查询下沉平台 API**：Tauri 2 的 Monitor 无「工作区」概念（只有
   size/position/scale_factor），避开任务栏必须 SPI_GETWORKAREA；用 windows crate
   （0.62 已在依赖树，不新增编译单元）+ `#[cfg(windows)]` 隔离，macOS 保持整屏算法。
